    1. 文章から、次のtokenを作る

    LLMは、入力された文章の続きとして出せるtokenに点数を付けます。点数を確率へ変え、一つ選んで文章の末尾に加える。この処理を繰り返すと、回答が伸びていきます。まず、その一回分の計算を追います。

    flowchart TD A["文章をtokenに分け
    ベクトルへ変換"] --> B["Attention・FFNで
    表現を変える"] B --> C["各候補の点数 logit"] C --> D["softmaxで確率へ
    tokenを選ぶ"] D --> E["選んだtokenを末尾に追加"] E --> A

    文章をtokenとベクトルにする

    Tokenは、モデルが扱う文字列の単位です。単語全体の場合もあれば、単語の一部や記号の場合もあります。文章をこの単位へ分ける道具がtokenizerです。

    Subword tokenizerは、単語より小さい文字列も部品として使います。たとえば unhappiness を un・happi・ness と分ける、と考えると仕組みをつかめます。これは模式例で、実際の区切りはtokenizerの語彙によって変わり、必ず語根や接辞に一致するわけではありません。

    Subword方式も、登録済みtokenの集合である固定語彙を使います。違うのは、完成した単語だけを登録するのでなく、部品を組み合わせて多くの単語を表せることです。日本語の「今日は晴れです」も、分割器によって区切り方とtoken数が変わります。

    Tokenはそのままでは計算できないので、数値の並びであるベクトル（vector）へ変換します。この学習済みの数値表現をembedding（埋め込み）と呼びます。たとえば [0.2, −0.5, 1.1] のような形です。各成分が一つずつ日本語の意味に対応するわけではありません。

    Attentionは、参照先の情報を重み付きで集める

    「クマは本を読んだ。それは面白かった」の「それ」を処理するとき、直前の「本」が手掛かりになります。Self-attentionは、同じ列の各tokenからどれだけ情報を受け取るかを計算する仕組みです。

    各tokenの表現から、照合する側のQuery（Q）、照合される側のKey（K）、受け取る情報のValue（V）を作ります。いずれも学習した変換で得るベクトルです。「参照先を探す質問」「見出し」「本文」という比喩は使えますが、実際に日本語の質問札が内部にあるわけではありません。

    一つのQueryを [1, 0]、参照先のKeyを下表の3つとします。内積（dot product）は、対応する成分を掛けて足す計算です。Key 1なら 1×2 + 0×0 = 2 になります。

    Query [1, 0] と3つのKeyを照合する仮想例
    参照先Key内積√2で割ったscore
    1[2, 0]2約1.414
    2[1, 1]1約0.707
    3[0, 2]00

    Keyの成分数を dk とすると、通常は内積を √dk で割ります。成分数が多いと内積の値も大きくなりやすいため、後の確率変換が極端になりにくいよう調整します。この例では2成分なので√2です。

    得たscoreは、まだ合計1の重みではありません。次のsoftmaxで変換してから、Valueを混ぜます。

    Softmax：点数を正の重みに変え、合計で割る

    Softmaxは、点数の並びを合計1の重みに変える計算です。まず各点数に指数関数 exp を適用し、その合計で割ります。exp(z) は ez と同じで、eは約2.718という定数です。負の点数も正の重みに変わります。

    先ほどのscore [1.414, 0.707, 0] を変換すると、expの値は約 [4.113, 2.028, 1]。合計は約7.141です。

    参照先1の重み = 4.113 / 7.141 ≈ 0.576

    参照先2の重み = 2.028 / 7.141 ≈ 0.284

    参照先3の重み = 1.000 / 7.141 ≈ 0.140

    重みの合計は1です。Valueの一成分をそれぞれ10、20、30とすると、受け取る値は次のようになります。

    0.576×10 + 0.284×20 + 0.140×30 ≈ 15.64

    実際のValueはベクトルなので、各成分について同じ計算をします。ここで得たものは文脈を取り込んだ表現であり、出力するtokenそのものではありません。

    この計算を全Queryについてまとめた式が、次のscaled dot-product attentionです。

    Attention(Q, K, V) = softmax(QKT / √dk) V
    QKT
    全Queryと全Keyの内積を並べた表。Tは行と列を入れ替える転置です。
    softmax
    各Queryの行ごとに、scoreを合計1の重みに変えます。
    最後のV
    その重みでValueを合計し、各Queryの出力ベクトルを得ます。

    定義：Transformer原論文、PyTorchのsoftmax仕様。上の数値は丸めて表示しています。

    Temperature：次のtokenの選ばれやすさを調整する

    Attentionなどの層で表現を変換したあと、モデルは語彙中の各候補にlogitという点数を付けます。ここでもsoftmaxを使いますが、今回は参照先の重みではなく、次に出力するtokenの確率を求めます。

    「今日は」の次を、説明用に「晴れ」「雨」「雪」の3候補だけとし、logitを [2, 1, 0] とします。expで変換すると [7.389, 2.718, 1]、合計11.107で割ると約 [0.665, 0.245, 0.090] です。

    Temperatureを使うときは、expの前にlogitを正の数Tで割ります。T=2なら [2, 1, 0] が [1, 0.5, 0] になり、点数差が小さくなります。

    pi(T) = exp(zi/T) / Σj exp(zj/T),　T > 0

    ziは候補iのlogit、Σjは全候補の合計、piは選択確率です。新しく加わった操作は「zをTで割る」だけです。

    同じlogit [2, 1, 0] に対する選択確率
    T晴れ雨雪
    0.586.68%11.73%1.59%
    166.52%24.47%9.00%
    250.65%30.72%18.63%

    Tを下げると最高点に集中し、上げると低い候補も選ばれやすくなります。この確率に従って抽選する方法がsamplingです。最大点を必ず選ぶgreedy decodingなら、正のTを変えても順位は変わらず、どの場合も「晴れ」を選びます。表は丸めにより合計が100%とわずかに異なる場合があります。[生成方法の公式解説]

    T=0について

    上の式にT=0は代入できません。APIによっては、T=0をgreedy decodingの特別指定として扱います。Tを下げることは正しさの保証ではなく、同じ誤った候補へ集中する場合もあります。

    選んだtokenを加えて、同じ処理を繰り返す

    生成済みのtokenを条件に次のtokenを作る方式を自己回帰モデル（Autoregressive Model、ARM）と呼びます。「猫」「が」「寝る」の3 tokenを作る仮想例なら、文全体の確率は次の積です。

    p(猫 が 寝る) = p(猫) × p(が | 猫) × p(寝る | 猫 が)

    縦棒 | は「右側を条件として」という意味です。長さLの列へ一般化すると、積を表す記号Πを使って書けます。

    p(x1:L) = Πt=1L p(xt | x<t)

    推論時は前のtokenが決まるまで、次の入力が完成しません。一方、学習時には正解の文章全体があるため、未来tokenを見えなくするcausal maskを使いつつ、多くの位置の予測を同時に計算できます。「モデル内部の演算」と「出力tokenを決める順序」の並列性は別です。

    語順と、モデル内部の部品

    位置情報がなければ、attentionは同じtokenの並び替えを語順として区別できません。RoPEは、QueryとKeyの座標を位置に応じて回転させ、内積に相対距離が反映されるようにします。文字を回すのではなく、数値ベクトルの変換です。

    Multi-head attentionは、異なる学習済み変換で複数組のQ/K/Vを作る方法です。各headがどんな関係を捉えるかは学習によって決まり、「主語専用」などの役割があらかじめ固定されているわけではありません。

    Attentionがtoken間で情報を集めたあと、FFN（Feed-Forward Network）が各tokenの表現を変換します。Transformerの層には、入力を足し戻す残差接続と、数値の大きさを整える正規化もあります。これらを重ねた表現から、最後にlogitを作ります。

    どの方向を読ませるかで、基本的な用途が変わる

    Encoder-only入力の前後BERT：分類や埋め込み
    Decoder-only生成済みの左側GPT：文章の続きを生成

    歴史的な位置づけ：word2vecとRNN

    Word2vecは近隣語の予測から単語ベクトルを学びますが、学習後の単語表では同じ語に固定のベクトルを割り当てます。たとえば英語の bank の「銀行」と「川岸」を、その都度別の表現にする仕組みではありません。

    RNNは文章を順に読み、過去の情報をhidden stateへ渡します。長距離の情報を多くの段階を介して伝える必要があり、計算も順番に依存します。Self-attentionは、離れたtokenを直接参照できる点が異なります。RNNが必ず過去を忘れるという意味ではありません。

    2. 出力の確率を、学習で変える

    推論では、学習済みの数値を使って回答を作ります。学習では、回答の誤りを手掛かりに、その数値であるパラメータを更新します。まず「何を良い出力とするか」を点数にする必要があります。

    予測の外れを損失として測る

    正解tokenへの確率が0.1より0.8の方が、良い予測です。次token予測では、正解確率の自然対数を取り、符号を逆にした負の対数尤度を損失に使います。自然対数lnはexpの逆の関数です。

    損失 = −ln(正解tokenの確率)

    確率0.1なら約2.303、確率0.8なら約0.223

    学習はこの損失を小さくする方向へ進みます。勾配（gradient）は、各パラメータを少し動かすと損失がどちらへ、どれくらい変わるかを表します。出力を計算するforward passのあと、backward passで勾配を求め、optimizerが更新量を決めます。

    同じモデルに、三種類の教材を与える

    大量の文章から続きを予測できても、そのまま質問へ親切に答えるとは限りません。教材を変えることで、基礎能力、指示への応答、人の選好を段階的に学ばせます。

    学習段階と、与える信号の違い
    段階教材主に教えること
    Pretraining
    事前学習    		大量の文章・コード言語、知識、構造のパターン
    SFT
    教師あり微調整    		指示と望ましい回答の組質問への答え方、出力形式
    Preference tuning
    選好調整    		どちらの回答がよいかという比較有用性、安全性、語調など

    SFTは良い回答の見本を与えます。選好調整は「別の回答よりこちらを好む」という相対情報を加えます。目的は重なり得ますが、教材が伝える情報は同じではありません。

    二つの回答の比較から、報酬モデルを学ぶ

    RLHFは、人のフィードバックを使う強化学習です。まず人が比較した回答対から、回答に点数を付けるreward modelを学びます。その点数を報酬として、LLMが好ましい回答を出しやすいように更新します。

    回答AとBへの内部scoreをrA、rBとすると、Bradley–Terry modelでは次の確率を使います。

    P(Aが好まれる) = exp(rA) / {exp(rA) + exp(rB)}

    rA=2、rB=0なら、7.389 / (7.389 + 1) ≈ 0.881。Aが好まれる確率は約88.1%です。同点なら50%になります。人の比較結果を説明できるようscoreを学ぶので、学習後は一つの回答だけにもscoreを付けられます。

    このscoreは真偽を測った絶対値ではありません。採点器の癖だけを利用して得点を上げるreward hackingを避けるため、元のモデルとの確率分布の違いをKL divergenceで抑える方法があります。PPOのclippingは、更新前後の選択確率の比が大きく変わりすぎないよう学習を制限する仕組みです。

    強化学習の用語をLLMへ対応付ける

    Policyは次tokenの選び方、stateはpromptと生成済みtoken、actionは次tokenです。語彙全体は選べる行動の集合であるaction spaceに当たり、選んだtokenを列へ追加すると次のstateになります。完成した回答への報酬を、それ以前のtoken選択へどう結び付けるかが学習の課題です。講義スライドの「environment＝tokens」は簡略表記として読みます。

    選好学習の背景：InstructGPT論文。PPOの詳細はLecture 5を参照。

    GRPOは、同じ問題への複数回答を比べる

    数学の答えの一致やコードのテスト通過は、自動で採点できます。こうした検証可能な報酬を使えば、回答前の途中のtoken列であるreasoning chain / Chain of Thoughtも含めて学習できます。最終答が正しいことは、途中の全手順が正しいことまで保証しません。

    PPOではvalue model（critic）が期待報酬を予測し、それと実際の報酬を比べます。GRPOは同じ問題から複数回答を作り、群の平均と比べることでcriticを省きます。基準よりどれだけ良いかを表す値がadvantageです。

    4回答の報酬を [1, 0, 0, 0] とします。平均は0.25。平均からの差は [0.75, −0.25, −0.25, −0.25] です。

    分散 = (0.75² + 0.25² + 0.25² + 0.25²) / 4 = 0.1875

    標準偏差 = √0.1875 ≈ 0.433

    advantage ≈ [+1.73, −0.58, −0.58, −0.58]

    分散は平均からの差を二乗した平均、標準偏差はその平方根です。この例は4で割る定義を使っています。差を標準偏差で割ることで、報酬のばらつきを基準にした値になります。

    Ai = {ri − mean(r)} / std(r)

    正のadvantageはその回答を出しやすく、負なら出しにくくする信号になります。全回答が同じ報酬ならstd=0で、この式は未定義です。実装では分母へ小さなεを足すなどの処理が必要になります。

    元のGRPOには、回答長で割るため長い誤答への罰が弱くなるlength biasなどの問題もあります。講義はDAPO、GRPO Done Right（Dr. GRPO）を改良例として紹介します。GRPOが常にPPOより優れるという意味ではありません。[原論文] [実装と改良点]

    学習量を増やす前に、教材の質を整える

    学習に使う文書集合をcorpusと呼びます。Data curationは、重複や誤情報を減らし、目的に合う資料を選ぶ作業です。量だけ増やすと、同じ表現や誤りを繰り返し学ぶ場合があります。

    Mid-trainingは、広い事前学習と用途別の微調整の間に、高品質・専門的な教材を追加する段階です。モデルが作ったsynthetic dataも利用できますが、低多様性の生成物を繰り返し学ぶと、元の分布の稀な特徴が失われるmodel collapseが懸念されます。

    これは合成データをすべて禁止すべきという意味ではありません。内容の検証、元データとの混合、多様性の確認が必要です。講義中の「検索結果の80%がLLM生成かもしれない」は問題意識を示す口頭例であり、確認済みの統計としては扱いません。

    大きなモデルには、相応のデータと計算が必要

    Scaling lawは、モデル規模・学習データ量・計算量と損失の関係を観測した経験則です。固定の計算予算をモデルの大型化だけへ使うと、読むtokenが足りずundertrainingになることがあります。

    講義はcompute-optimalな配分の目安として、パラメータ数Nに対する学習token数Dを次のように紹介します。

    D ≈ 20N

    N=100BのBは10億なので、1,000億パラメータです。20倍すると2兆token（2T）になります。これはChinchilla研究に基づく歴史的な目安で、モデル構造・データ品質・推論費用まで考えた全用途に共通の最適比率ではありません。

    3. 計算・メモリ・転送を減らす

    モデルを動かす費用は、掛け算の回数だけでは決まりません。過去の計算をやり直す費用、保存する量、メモリやGPUの間でデータを運ぶ時間もあります。技術名ではなく、何を減らすかで分けます。

    KV cacheとGQA：過去の計算を残し、共有する

    KV cacheは、生成済みtokenのKeyとValueを保存する仕組みです。新しいtokenを作るたびに過去のK/Vを作り直さずに済みます。ただし、新しいQueryが過去のK/Vを参照する計算や読み出しは残ります。

    MHAでは各attention headが別のK/Vを持ちます。MQAは全Query headで一組のK/V headを共有し、GQAはQuery headをグループに分けてK/Vを共有します。たとえば8個のQuery headが2組のK/Vを共有するなら、保存するK/V head数は8から2へ減ります。

    GQAはモデルの設計変更なので、同じ答えを保つだけの実装最適化とは違います。共有量と性能の関係は学習条件にも依存します。

    MoE：選んだexpertの出力だけを混ぜる

    MoE（Mixture of Experts）はFFNを複数のexpertへ分け、入力tokenごとに一部を実行する設計です。Gateがexpertへ点数を付け、上位k個（Top-k）を選んで、その出力を混ぜる重みを決めます。

    8 expertから2つを選んだとします。出力を [2, 0] と [0, 4]、重みを0.75と0.25とする仮想例では、次の計算になります。

    0.75 × [2, 0] = [1.5, 0]

    0.25 × [0, 4] = [0, 1]

    [1.5, 0] + [0, 1] = [1.5, 1]

    この重み付き合計を一般化すると、fe(x)をexpertの出力、ge(x)をgateの重みとして書けます。

    y = Σe∈Top-k ge(x) fe(x)

    yは次の層へ渡すベクトルです。Temperatureが変えるtokenの選択確率とは別の値です。

    MoEは実行するactive parametersを絞りますが、全expertの重みを保存する容量は必要です。Gateの処理、expert間通信、負荷の偏りもあるため、8個中2個を使っても4倍速になるとは限りません。kの変更も学習済みモデルに自由に適用できるとは限りません。

    FlashAttention：大きな中間表を保存しない

    通常のattention式は、関連scoreをS、softmax後の重みをP、出力をOとして、S=QKᵀ/√d、P=softmax(S)、O=PVと分けられます。N tokenをまとめて処理すると、SとPはN×Nの表です。

    HBMは大きなデータを置くGPUメモリ、SRAMは演算器の近くにある小容量で高速なメモリです。素直な実装はSをHBMへ保存して読み直し、Pも保存して読み直します。FlashAttentionは、SRAMに収まる小さなblock / tileずつ計算し、この全体表の保存を避けます。

    ここで疑問になるのは、softmaxは全体の合計で割るのに、小分けにして同じ答えが出るのかという点です。

    小分けにしても、分母は全体でそろえる

    一つのQueryについて、4参照先の exp(score) を [2, 1, 3, 1]、Valueの一成分を [10, 20, 30, 40] とします。Softmaxの分母は7なので、出力は次の値です。

    出力 = (2/7)×10 + (1/7)×20 + (3/7)×30 + (1/7)×40

    　　 = (20 + 20 + 90 + 40) / 7 = 170/7 ≈ 24.29

    前半と後半を別々に計算し、重みの合計Lと、出力用の合計Uだけを引き継いでみます。

    二つのblockの合計を合わせる
    範囲L：exp(score)の合計U：exp(score)×Valueの合計
    前半2個2 + 1 = 32×10 + 1×20 = 40
    後半2個3 + 1 = 43×30 + 1×40 = 130
    全体3 + 4 = 740 + 130 = 170

    最後にU/Lを計算すれば、やはり170/7です。前半のscoreをすべて保存しておく必要はありません。一方、blockごとの出力 40/3 と 130/4 を単純平均すると約22.92になり、間違います。重みの合計3と4を捨ててはいけないためです。

    この合算を数値的に安定させた方法がonline softmaxです。Onlineは「順次更新する」の意味で、ネット接続ではありません。実際には大きなexpによる桁あふれを避けるため、最大scoreも保持して合計の尺度を合わせます。[原論文 §3.1]

    最大値が変わるときの計算

    Softmaxは、全scoreから同じ最大値mを引いても変わりません。分子と分母が同じ exp(−m) 倍になるためです。そこで L=Σ exp(s−m)、U=Σ exp(s−m)Vを保持します。

    前半の最大値をmA、後半をmB、新しい最大値をm=max(mA,mB)とすると、以前の合計を同じ尺度へ直して足せます。

    L = exp(mA−m)LA + exp(mB−m)LB

    U = exp(mA−m)UA + exp(mB−m)UB

    上の例ならmA=ln2、mB=ln3です。前半のL=1.5、U=20を2/3倍し、後半のL=4/3、U=130/3へ足すと、全体はL=7/3、U=170/3。U/Lは再び170/7になります。

    再計算が増えても、なぜ速くなるのか

    学習のbackward passでは、forward時のscoreや重みが再び必要です。FlashAttentionはQ/K/V、出力、正規化情報などから、必要な中間blockを再計算します。大きなS/PをHBMへ保存して読み直す代わりに、小さな演算をやり直します。

    増えた演算の時間より、減った転送の時間が大きければ、処理全体は速くなります。演算回数であるFLOPが少ないことと、実時間が短いことは同じではありません。転送待ちが速度を制限する状態をmemory-bound、演算が制限する状態をcompute-boundと呼びます。

    Exact attentionは、同じattention式を計算する意味です。全組み合わせの計算が不要になるわけではなく、計算順と保存方法を変えています。浮動小数点の丸めにより、通常実装とbit単位で一致する保証はありません。

    大きさの目安とGPUの仕様

    N=4,096ならSは16,777,216要素です。1要素2byteなら1 headの一つの表だけで32MiBになります。原論文のA100例はHBM 40〜80GB、帯域1.5〜2.0TB/s、SRAMは各SM当たり192KB、帯域の推定はGPU全体で約19TB/sです。容量・帯域・集計単位を区別して読みます。速度向上率はGPU、入力長、headの次元、実装に依存します。

    複数GPUへ、何を分担するか

    Data parallelismは、各GPUに同じモデルを置き、異なる学習例を処理して勾配を集約します。128件を8 GPUへ分けるなら担当は16件ずつです。Model parallelismは、モデルの層や行列を分割し、一つの入力を複数GPUで計算します。

    どちらもGPU間通信が必要です。これは一台の中の転送を減らすFlashAttentionとは別の軸で、組み合わせて使えます。

    4. 外部を調べ、道具を使い、結果を確かめる

    学習したモデルの重みは、今日のニュースや非公開資料に合わせて自動更新されるわけではありません。必要な情報を実行時に渡す経路と、外部操作を行う経路を追加します。

    RAGは、回答前に根拠を渡す

    RAG（Retrieval-Augmented Generation）は、外部資料を検索し、関連する本文をpromptへ追加して回答を生成する方法です。学習データの時点の限界であるknowledge cutoffや、モデルが学習していない社内知識を補います。

    講義は二段階検索を紹介します。Bi-encoderで質問と文書を別々にベクトル化し、多数の候補から近いものを取ります。次にcross-encoderが質問と候補文書を一緒に読み、関連度を再採点するrerankingを行います。上位k件（top-k）の本文を回答の根拠にします。

    最初の検索を高速に、少数候補の比較を丁寧にする設計です。RAG全般がベクトル検索を必須とするわけではなく、キーワード検索なども使えます。

    資料を小さな断片へ分けるchunking、古い版の除外、出典の保存も重要です。必要な資料が検索漏れしたり、LLMが本文を読み違えたりする可能性は残るため、出典を示すだけで正答を保証できるわけではありません。

    Tool callingは、外部プログラムへ操作を依頼する

    予約の確定やデータベース更新は、資料を読むだけでは実行できません。Tool callingでは、LLMがtool名と引数を出し、周囲のプログラムが実行して結果を返します。LLM自身に無制限の操作権限があるわけではありません。

    Schemaは引数名・型・必須項目などの規則です。Schemaに合うことと、正しい操作を選んだことは別です。権限や送信先、利用者の意図も実行側で確認します。

    結果を観測して次の操作を選ぶ反復を持つ仕組みがagentです。RAGは外部知識を読む機能、tool callingは検索や計算、更新を依頼する機能であり、一つのagent内で組み合わせられます。

    評価には、採点基準とその偏りを含める

    「正しい」「簡潔」「根拠がある」を採点条件として書き分けたものがrubricです。LLMの回答は言い換えが多いため、一つの模範文との一致だけでは十分に評価できません。

    評価の方法と、主な見落とし
    方法何を比べるか注意点
    BLEU / ROUGE / METEOR参照文との語句の一致や対応意味が正しい別表現を低く採点し得る
    LLM-as-a-JudgePrompt・回答・rubricを読んだ判定判定役にも誤りや偏りがある
    人手校正一部の回答を人が採点し、Judgeとの不一致を確認費用と評価者間のばらつきがある

    Judgeには、候補の提示順を好むposition bias、長い回答を好むverbosity bias、自分と同系列の出力を好むself-enhancement biasがあります。候補順の入替え、明確な基準、理由を先に出す判定、二値判定、人手との照合を組み合わせます。

    公開benchmarkは知識、推論、コード、安全性などの一面を測る試験です。最終選定には、自分の用途に近いデータでの評価と、費用・待ち時間も必要です。

    用途ごとに、確認する対象を変える

    講義は、コード作成、自然言語からSQLなどを作るtext-to-query、会話支援、創作の初稿、学習時の案出しを挙げます。どれも同じ方法で検証できるわけではありません。

    コードにはテストとreview、検索回答には出典と鮮度、創作には目的と権利の確認が要ります。主張を資料で裏付けられる度合いがgroundednessです。外部へ変更を加えるなら、変更を取り消すrollbackも設計します。

    作業をつなぐほど、一回の誤りの影響が広がる

    各stepが独立に1%の確率で失敗する、と仮定します。1 stepの成功確率は0.99なので、10 step全部の成功は 0.9910 ≈ 0.904。少なくとも一回の失敗は、その反対です。

    P(少なくとも1回失敗) = 1 − (1 − p)n

    p=0.01、n=10なら、約9.6%

    実際の失敗には相関があります。最初の誤解が後続判断へ連鎖する場合も、確認stepが誤りを取り除く場合もあるため、この式は実際の事故率の予測ではありません。

    外部文書中の命令を正規の指示と取り違える攻撃がprompt injection、許可されない場所へ秘密情報を持ち出すことがdata exfiltrationです。外部データと指示の境界、最小権限、重要操作の承認、実行記録が必要になります。

    講義は自然言語によるagent作成の民主化や、ChatGPT Atlasなどのbrowser支援、将来のOSレベル支援を展望します。同時に、共感と根拠を備えた顧客対応を本当に完遂できるかを課題とします。利用中に知識を更新するcontinual learning、個別化とprivacy、判断のinterpretability、事実と異なる内容をもっともらしく生成するhallucinationも未解決です。

    5. 画像を、Transformerが読める列にする

    画像にもtokenに相当する単位を作る

    Transformerが計算するのは文字そのものではなくベクトルの列です。画像の各領域をベクトルへ変換すれば、同じattentionで領域同士の関係を扱えます。

    CNNは近くの画素を同じフィルタで調べます。この局所性のように、学習前から設計に組み込む仮定をinductive biasと呼びます。ViT（Vision Transformer）は近所だけを特別扱いせず、画像の小領域同士をattentionで関連付けます。

    局所性の仮定が弱いと少ないデータでは学びにくい場合がありますが、大量のデータから柔軟な関係を学べます。講義は大規模学習したViTがCNNを上回った研究を紹介します。「弱い仮定なら常に優れる」という意味ではありません。

    224×224の画像から、196個のpatchを作る

    画像を16×16画素の正方形で区切ると、縦横に14個ずつ、196個のpatchができます。RGB画像なので、一つのpatchには 16×16×3 = 768 個の数があります。

    高さH、幅W、patchの一辺Pに対し、patch数Nは次の式です。HとWがPで割り切れるように、必要なら画像を切り抜く・余白を足すなどの前処理をします。

    N = (H/P) × (W/P) = HW/P²

    各patchの数値を一列にする操作がflattenです。その列に学習した行列Eを掛けて、モデルの幅Dに合わせます。入力が768成分なら、Eは768×Dの行列です。

    先頭に集約用のCLS tokenを一つ加え、各tokenに位置埋め込みEposを足します。この段階だけを式にすると次のようになります。

    z0 = [xCLS; x1E; …; xNE] + Epos

    セミコロンはtokenを列として並べる記号です。z0はencoderへの入力で、ここでは197×Dの形になります。encoderをL層通した先頭tokenの表現を、分類部へ渡します。

    予測クラス ŷ = Head(zLCLS)

    Patchの辺を16から8へ半分にすると、枚数は縦横2倍ずつ、合計4倍です。細かい情報を扱える一方でattentionの計算とメモリは重くなります。[ViT原論文]

    VLMは、画像の特徴を文章生成へ渡す

    VLM（Vision-Language Model）は画像と文章を扱うモデルです。分類名を一つ返すViTと違い、「この画像には何がある？」という質問に文章で答えます。

    講義は二つの接続方法を示します。LLaVA型の連結方式は、画像ベクトルをprojectorで言語モデルの入力次元へ合わせ、text tokenと同じ列へ並べます。Llama 3論文の例のcross-attention方式は、text側のQueryが、別に保持した画像のKey/Valueを参照します。

    どちらも画像と言語を結びますが、融合する場所が違います。画像tokenが長い場合の費用や、細かな文字、個数、位置関係の読み違いは残ります。

    6. 左から順に書かない、拡散による生成

    自己回帰生成は、直前までのtokenが決まるのを待ちます。別の順序で複数箇所を生成できれば、この待ち時間を減らせる可能性があります。講義は画像で使われたdiffusionの発想を、文章へ移す研究を紹介します。

    画像diffusionは、ノイズを加える過程の逆を学ぶ

    画像を浮動小数点の画素値として表し、ランダムな揺らぎであるGaussian noiseを段階的に加えます。元画像がわかっているので、学習では「何をどれだけ加えたか」を正解にできます。

    ノイズを加える方向がforward process、それを減らす方向がreverse processです。生成時は新しいノイズから始めるので、特定の元画像を復元しているわけではありません。学習した画像の分布に沿った新しい画像を作ります。

    講義はミケランジェロを引き合いに、「大理石から彫刻を削り出す」とたとえます。これは反復的な生成の直観で、ノイズの中に完成画像が最初から隠れているという意味ではありません。

    拡散過程の記号

    q(xt|xt−1)はノイズを一段加える条件付き分布、pθ(xt−1|xt)はモデルが学ぶ逆向きの分布です。tは段階、θは学習パラメータを表します。厳密なDDPMの学習目的の導出は、この講義の範囲を超えるため原論文を参照します。

    Masked diffusionは、伏せたtokenを予測する

    Text tokenは離散的な選択なので、画像の画素へ連続ノイズを足す操作はそのまま使えません。講義で扱うMasked Diffusion Model（MDM）では、tokenを隠すMASKを使います。

    学習では正しい文の一部をMASKに変え、元のtokenを当てます。生成ではpromptを条件として残し、回答領域のMASKを反復して予測・確定します。固定して与える条件をconditioningと呼びます。

    3つの位置を復元する模式例。実際の分割や確定順はモデル依存
    段階回答領域何が決まったか
    開始[MASK] [MASK] [MASK]回答の内容はまだ決まっていない
    更新1今日は [MASK] よい二つの位置を確定
    更新2今日は 天気が よい残りを前後の文脈から補う

    完成文は最初から与えられていません。各更新でモデルが候補を作ります。誤ったtokenを早く確定すると後の候補を狭めるため、確定位置の選び方や再MASKの扱いが重要です。すべての拡散型LLMが同じ手順を使うわけではありません。[LLaDA原論文]

    速さは、反復回数と一回の計算量で決まる

    出力長をN、拡散の更新回数をKとすると、自己回帰では概ねN回の逐次生成、拡散ではK回の更新が必要です。ただし拡散の一回は複数位置を処理するため、KがNより小さいだけで速いとは言えません。実時間と品質を一緒に比較します。

    生成方法の違い
    観点自己回帰Masked diffusion
    確定する順序基本は左から右複数位置を反復的に確定
    推論の特徴過去のK/Vを再利用しやすい一回に複数位置を処理できる可能性
    残る課題長い出力の逐次待ち反復回数、確定誤り、最高水準の品質

    前後のコードを残して中央だけ埋めるfill-in-the-middleは、両側を参照する生成と相性がよい用途です。自己回帰モデルでも専用の学習や入力形式で対応できます。

    講義はLLaDA、Googleの実験、Inceptionなどを挙げ、長文生成で約10倍の速度向上という報告を紹介します。タスク、生成長、更新回数、GPU、品質条件に依存する結果で、常時の保証ではありません。Reasoningや逐次的なtool利用をどう組み合わせるかも研究課題です。

    7. モデルを選び、研究の変化を読む

    異なる分野へ、どの部品を移せるか

    文章、画像、音声といった情報の種類をmodalityと呼びます。Textから画像へattentionを移すViTと、画像からtextへ生成の発想を移すdiffusionは、分野間のcross-pollinationの例です。

    講義は推薦・音声・Diffusion Transformerへの展開も挙げます。また、画像中の文字を認識するOCRについて、DeepSeek-OCRを少数のvision tokenから多くのtext tokenを復元する例として紹介します。圧縮すれば計算量を減らせる可能性がありますが、細字や配置情報の欠落に注意が必要です。

    Text用RoPEの位置は一次元です。画像では縦・横を区別するため、二次元の位置表現へ拡張します。共通部品を使えても、情報の配置まで同じではありません。

    Transformerの内部設計にも、選択肢が残る

    設計を構成する各部品は、何を変えるかが異なります。名称だけで優劣を決めず、改善したい対象と対応させます。

    講義で挙がった設計項目
    項目変えるもの代表例
    Optimizer勾配から更新量を決める方法AdamW、Muon、MuonClip
    Normalization層内の値の尺度と、整える場所LayerNorm / RMSNorm、post-norm / pre-norm
    Activation線形変換の間に加える非線形性ReLU、GELU
    Attention headK/Vを共有する範囲MHA、MQA、GQA
    FFNTokenごとに動かす変換Dense、MoE
    深さ・幅層数と各層の表現容量層数、head数、FFN幅

    Kimi K2のMuonClipは、optimizerも研究対象であることを示す講義中の例です。各項目は独立ではなく、層を深くすれば正規化、MoEを増やせば通信と負荷分散も考える必要があります。

    Pareto frontierで、明確に劣る選択肢を除く

    仮にモデルAが10円で品質80、Bが10円で85、Cが5円で82とします。AよりBの方が同じ料金で高品質なので、Aは候補から外れます。一方、BとCは品質と費用の交換があり、どちらにも選ぶ理由があります。

    別候補より同額以上で品質が同等以下、かつ少なくとも一方で劣る候補をdominatedといいます。そうした点を除いた境界がPareto frontierです。待ち時間（latency）や安全性を加えるなら、比較軸も増えます。

    SLM（Small Language Model）は、限定された用途で十分な品質を低費用で得る選択肢です。最高性能のモデルでも提供費用が高すぎれば採算が合いません。公開scoreは候補の絞り込みに使い、実際の用途で選びます。

    計算する場所自体を変える研究

    Analog in-memory computingは、K/Vを保存する場所の内部や近くで演算し、データ転送を減らす考え方です。電圧・電荷・パルスなどの連続的な物理量を使う点が、通常のデジタル計算と異なります。

    講義は専用セルでattentionを扱う研究を紹介します。ただし、これはFlashAttentionのように同じ式の計算順だけを変えるものとは限りません。原論文では回路の制約に合わせた活性化やモデルの適応も扱います。

    大きな高速化・省エネルギー化が期待されますが、比較対象はattentionの演算部分です。LLM全体の実運用で同じ倍率を保証するものではありません。信号のノイズ、精度、変換回路、汎用性まで含めて評価する必要があります。

    原論文の性能比較と、その範囲

    参照したarXiv v2の§2.7では、RTX 4090との比較で速度約300倍、エネルギー削減約90,000倍と報告しています。GPUの測定と、専用回路のシミュレーションに基づく推定を比べた結果です。H100やLLM全体にそのまま適用できる数字ではありません。

    研究の主張を、条件と実装へ戻す

    新しい手法に出会ったら、「何を固定して、何を変え、何が良くなったか」を確認します。Prompt、data、生成回数、temperature、GPU、品質条件が違えば、scoreや速度だけの比較はできません。

    用語から本文へ戻る
    • tokenizer・embedding：文章を分割し、数値表現へ変換する。
    • Q/K/V・内積：参照先を照合し、情報を重み付きで集める。
    • softmax：点数を合計1の重みにする。
    • logit・temperature：次tokenの点数と選択確率を扱う。
    • loss・gradient：予測誤差を測り、更新方向を求める。
    • advantage：報酬を比較基準からの差として評価する。
    • KV cache・GQA：過去のK/Vを保存し、head間で共有する。
    • MoE：選んだexpertを実行して出力を混ぜる。
    • FlashAttention：中間表全体の保存を避けてattentionを計算する。
    • RAG・groundedness：外部資料を使い、主張を根拠で裏付ける。
    • patch・CLS：画像をtoken列へ変え、全体の情報を集める。
    • MASK・conditioning：固定した条件の下で伏せた位置を予測する。
    • Pareto frontier：品質と費用の両面で劣らない候補を残す。

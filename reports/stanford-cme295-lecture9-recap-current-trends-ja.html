    1. 最終回のメニュー：復習を「部品表」ではなく因果に戻す

    身近な地図にたとえると、最終回は新しい道を増やすのでなく、これまでの道がどこでつながるかを確かめる回である。まず講義全体の順序を確認する。前半の復習は新情報を足すためでなく、後半のViTと拡散LLMがどの既習概念を借りているかを見失わないためである。講師は「recap、2025年のtrend、closing thoughts」の三部構成を提示した。

    次の表は、Lecture 1〜8を番号順ではなく、後半の新規トピックへ何を受け渡すかで三つにまとめたものだ。ここでいうvectorは情報を数の並びで表したもの、patchは画像を小さな四角形に区切った一片、外部化はモデル内部の記憶だけに頼らず、資料・道具・評価基準を外から与えることを指す。

    復習の連鎖中心の問い後半で再利用される先
    L1–2数値で表したtoken同士の関係をどう計算するか画像patchと縦横の位置情報
    L3–6大規模な生成モデルをどう学習・推論するか自己回帰生成と拡散生成の比較
    L7–8外部資料・tool・評価基準をどう使うか安全な実運用

    この表は回ごとの目次ではなく依存関係である。後半の「新しいtrend」は前半の土台なしには評価できず、逆にtrendは前半の設計選択が未完成であることを示す。

    2. tokenからattentionへ：Transformer以前の問題を思い出す

    文章を読む前に、モデルが扱うtoken、つまり計算のために区切った小さな単位を考える。人には unhappiness は一語でも、世の中のすべての語を辞書に登録することはできない。そこでsubword tokenizer（未知の語も、再利用できる文字の部品へ分ける仕組み）は、たとえば unhappiness を un + happi + ness のように分ける。この分割なら初めて見る語にも既知の部品を使える。

    講義の要点。 分けたtokenはvector（多数の数を並べた座標）に変換する。意味や使われ方を表すその数値表現をembeddingという。word2vecは、近くに現れる語を予測してembeddingを学ぶ代表例だが、同じ語には同じvectorを与えやすい。たとえば「bank」が川岸か銀行かを文脈で変えにくい。RNN（読んだ順に情報を渡す再帰型ニューラルネットワーク）は、ここまで読んだ内容をhidden state（途中までの読書メモに当たる内部の数値）へ順にしまう。長い文ではこのメモが薄れ、遠くのtokenを直接結びにくく、並列計算もしにくい。そこでTransformerはself-attention（各tokenが同じ列の必要なtokenを選んで読む計算）を使う。式ではQueryを「いま探す質問札」、Keyを「照合する見出し札」、Valueを「実際に受け取る本文」として読む。

    Attention(Q,K,V) = softmax(QKᵀ / √dk) VQ = 今この位置が探す問い、K = 各位置の照合札、V = 実際に受け取る内容、dk = Keyの次元数。QKᵀは全組合せの関連度、√dkは内積が大きくなり過ぎないための除算、softmaxは各Queryの重みを合計1にし、最後にVを重み付き平均する。

    式は、全tokenを同じ強さで読むという意味ではない。たとえば「それ」が何を指すかを探すとき、そのQueryは対応しそうな名詞のKeyに強く反応し、そのValueを多く受け取る。遠い関係も一層で直接扱えるため、次節の位置情報、そして後半の画像patchを読む基礎になる。

    3. 語順と効率を与える：RoPE、GQA、Transformerの三形式

    self-attentionはtoken同士の関係を計算できるが、そのままでは「何番目のtokenか」を知らない。たとえば「犬が人を追う」と「人が犬を追う」は単語が同じでも順序で意味が変わる。この節では、順序を伝えるRoPEと、生成時のmemoryを減らすGQAを説明する。

    講義の要点。RoPE（Rotary Position Embedding）は、tokenの位置に応じてQueryとKeyの数値vectorを異なる角度で変換する。ここでいう「回転」は文字を回すことではなく、vectorの座標を数学的に変換することだ。二つのvectorの照合結果に位置の差が反映されるため、「近いtokenか、遠いtokenか」をattentionが利用できる。

    Attention headは、token間の関係を読む独立した計算単位である。複数headを使うと、あるheadは主語と動詞、別のheadは代名詞と参照先というように、異なる関係を並行して学べる。生成時には過去tokenのKeyとValueをKV cacheへ保存し、同じ計算のやり直しを避けるが、文章が長いほどmemoryを消費する。GQA（Grouped-Query Attention）は、複数のQuery headでKey/Valueを共有し、性能を大きく落とさずKV cacheを小さくする設計である。

    位置を与えた同じattentionでも、どの方向のtokenを見せるかで役割が変わる。次の表は三形式を「見える範囲」と「主な仕事」で比較する。

    形式読む範囲主な仕事
    Encoder-only（BERT）両方向分類・embedding
    Decoder-only（GPT）左側のみ次token生成
    Encoder–decoder（T5）入力全体＋生成途中入力を別textへ変換

    この表が示すのは優劣ではなく情報の見え方である。後のViTは分類に強いencoderの発想を、VLMと通常のLLMは生成するdecoderの発想を主に使う。

    4. LLMの規模を使い切らない：MoEと確率的decoding

    大きなmodelを毎回まるごと動かすと、回答のたびに多くの計算が必要になる。この節では、tokenごとに必要な専門部分だけを動かすMoEと、次のtokenをどの程度ランダムに選ぶかを決めるtemperatureを分けて説明する。

    MoE（Mixture of Experts）では、通常のTransformerにある大きなFFNを複数のexpert（別々の変換を学ぶ小さな専門ネットワーク）に分ける。Gateは受付係のように各tokenを採点し、上位k個のexpertだけへ送る。

    MoE: y = Σe∈Top-k ge(x) fe(x)
    x = 入力tokenの表現、fe = expert eの変換、ge = gateが付けた重み、Top-k = 実際に動かす上位k個のexpert。すべてのexpertを毎回動かさないため、総parameter数を増やしても1 token当たりの計算を抑えられる。
    Temperature: pi(T)=exp(zi/T)/Σjexp(zj/T)
    ziは候補token iへmodelが付ける確率化前の生の点数（logit）、Tはtemperature。Tを下げると点数差が強調されて上位候補へ集中し、上げると確率分布が平らになって低順位の候補も選ばれやすくなる。

    MoEはmodel全体を小さくする技術ではなく、1回の推論で動かすactive parameterを一部に絞る技術である。temperatureはmodelの知識量を変えず、同じlogitから作る確率分布の形を変える。次節では、model規模だけでなく学習dataと計算量も釣り合わせる必要があることを見る。

    5. Scaling law：parameter、data、computeを同時に考える

    modelは大きければよいとは限らない。学習に使える計算量が同じなら、modelの大きさと読ませるdata量を釣り合わせる必要がある。Scaling lawは、parameter数・学習token数・計算量を増やしたとき、未学習dataに対する誤差がどう変化するかを観測した経験則である。parameterだけ増やして学習tokenが不足すると、modelの容量を使い切れないundertraining（学習不足）になる。

    D ≈ 20ND = 学習token数、N = parameter数。講義が紹介した当時の目安では、100B（1,000億）parameterなら約2T（2兆）tokenを学習に使う。この比率はcompute-optimal研究から得たrule of thumbであり、model構造・data品質・tokenizer・計算予算が変わっても常に成り立つ法則ではない。

    図表の読みは「大きいほど常に勝つ」ではない。固定予算でdataを不足させた巨大modelは、より均衡したmodel/data配分より悪くなり得る。続くFlashAttentionは、同じ学習目的をより少ないmemory movementで実行する工夫である。

    6. FlashAttentionと分散学習：演算回数だけでは遅さを説明できない

    速さは計算回数だけで決まらない。GPUでは、大量の数値をmemoryから演算器へ運ぶ時間も大きな負担になる。この節では、容量は大きいが転送が比較的遅いHBMと、容量は小さいがchip内で高速なSRAMを使い分けるFlashAttentionを説明する。

    講義の要点。FlashAttentionはattentionの答えを近似するのでなく、計算を小さなblockへ分け、必要なdataをSRAMに置いて処理する。巨大な中間行列をHBMへ何度も保存・読出しせず、必要な値は再計算することでdata転送を減らす。Data parallelismは異なる学習例を複数GPUへ分け、model parallelismはmodel自体を分割して、一度のforward pass（入力をmodelへ通して出力を得る1回の実行）を複数GPUで担う。

    この図の教訓は「演算を少し増やしても、data転送を大きく減らせば全体は速くなる」ことだ。FLOPは浮動小数点演算の回数、bottleneckは全体の速度を制限する最も遅い部分を指す。この発想は後半のanalog in-memory attentionまで連なる。

    7. 三段階学習：能力、指示追従、選好を混ぜない

    人が本を読んでから問題の解き方を学び、最後に良い答え方を覚えるように、学習信号には役割分担がある。hardware上で学習できるようになったら、次はどんな信号で何を変えるかを分ける必要がある。pretrainingからpreference tuningへの順序は、後のreasoningを理解するための基準線になる。

    三段階を混同しないため、次の表では各段階のdataと、そこで主に変わる能力を対応させる。

    段階主なdata主に得るもの
    Pretraining大量text/code次token予測、言語・知識の型
    SFT高品質な入出力対指示追従、応答形式
    Preference tuning比較・選好有用性、安全性、tone

    表は後段ほど「より高性能」になる順位表ではない。SFTだけでは望ましくない応答を比較対象として直接下げにくいため、第三段階は「何をしないか」を含む相対信号を加える。

    8. RLHF：LLMをpolicyとして見て、選好を報酬へ変える

    人が二つの回答を比べて「こちらがよい」と言う情報を、モデルの学習にどう戻すかを考える。三段階の最後を理解するため、LLMのtoken生成を強化学習の言葉へ翻訳する。これはreasoningのGRPOへ自然に進むための共通語彙である。

    講義の要点。強化学習の用語へ対応付けると、policy（行動の選び方）がLLM、state（現在の状況）がpromptと生成済みtoken、action（次の行動）が次token、action space（選べる行動の集合）が語彙全体、reward（結果への評価値）が完成応答のscoreに当たる。tokenを選ぶたびに、そのtokenが列へ追加されて次のstateになる。

    Bradley–Terry modelは、二つの応答のscore差から「どちらが好まれる確率が高いか」を表す。人が二回答を比べたpairwise dataでreward model（応答へ1つの評価点を付けるmodel）を学習すると、運用時には一つの応答だけでもscoreを出せる。

    P(yi ≻ yj) = exp(ri) / (exp(ri)+exp(rj))yi, yj = 同一promptへの二応答、≻ = 前者を好む、r = reward modelのscalar score。絶対的な「正しさ」ではなく、二つの相対順位を学ぶ式である。

    rewardだけを最大化すると、内容を本当に改善せず採点器の癖だけを利用するreward hackingが起き得る。そこでKL divergence（二つのtoken確率分布がどれだけ異なるかを測る量）をpenaltyとして加え、SFT済みmodelから離れ過ぎないようにする。PPOではさらにclippingを使い、一度の更新でtokenの選択確率が急変するのを抑える。この「よい出力を増やす」と「既存能力を壊さない」の二目的が次節にも残る。

    9. Reasoning：答えの前に推論chainを出し、検証可能な報酬で強化する

    数学の答えやprogramのtest結果は、自動で正誤を確認できる。この性質を使えば、最終回答だけでなく、回答前に生成する途中のtoken列であるreasoning chainも改善できる。この節では、PPOとGRPOが「実際の報酬を何と比べるか」という違いを説明する。

    Baselineは「この状況なら通常どれくらいの報酬を得られそうか」という比較基準で、advantageは実際の報酬がその基準よりどれだけ良いか・悪いかを表す。PPOではcritic（value model）が期待報酬を予測する。GRPOでは同じpromptから複数回答を作り、その群の平均報酬をbaselineにするため、criticを省ける。

    Ai = (ri − mean(r)) / std(r)Ai = i番目の回答のadvantage、ri = その回答の報酬、mean(r) = 同じpromptから作った回答群の平均報酬、std(r) = 報酬のばらつき。平均より高い回答は正、低い回答は負のadvantageになり、今後の生成確率を調整する基準になる。

    GRPOはvalue modelを持たずに済む一方、元の式で回答長ごとに正規化すると、短い誤答より長い誤答を弱くしか罰しない場合がある。講義が挙げたGRPO Done RightやDAPOは、このlength bias（回答長によって学習の重みが偏る問題）を修正する研究である。

    10. RAG：固定重みの外から、最新・私有の知識を読む

    modelの記憶だけでは、今日のニュースや社内文書を正確に答えられない。Knowledge cutoffは学習dataが反映されている時点の限界である。そこでRAG（Retrieval-Augmented Generation／検索拡張生成）は、回答前に外部資料を検索し、関連する本文をpromptへ追加してから回答を作る。

    Bi-encoderは質問と文書を別々にvector化し、近いvectorを高速に探して候補を絞る。次にcross-encoder rerankerが質問と各候補文書を一組ずつ同時に読み、より詳しく再採点する。最後に上位k件（top-k）の本文をpromptへ追加し、LLMへ回答を生成させる。

    この図が教えるのは、RAGがmodelの重みを更新しない外部知識経路だということだ。検索漏れ、誤順位、contextの誤用は最後のLLMが流暢でも残る。次節のtool callingは「読む」のではなく外部世界へ「作用する」経路である。

    11. Tool callingとagent：答えるだけのLLMを、観測と行動のloopへ置く

    RAGは資料を読む仕組みだが、予約の確定、メール送信、database更新のように外部の状態を変える操作は別の仕組みが必要になる。Tool callingでは、LLMが利用するtoolと引数を選び、仲介programが安全性を確認して実行し、その結果をLLMへ返す。この反復を行うsystemをagentまたはagentic workflowと呼ぶ。

    flowchart LR Q[ユーザー質問]-->L[LLM] L-->T[tool選択・引数] T-->M[仲介層が検証・実行] M-->R[結果] R-->L L-->A[最終応答]

    図をクリックすると拡大できます。

    図の重要点は、LLM自身がAPIを直接実行するのではないことだ。仲介層は実行可能な操作を制限し、schema（toolへ渡せる引数名・data型・必須項目の規則）に沿っているかを検証する。現代agentはRAGとtool callingを組み合わせるが、stepが増えるほどtool選択・引数・実行順・結果の統合のどこでも失敗し得る。

    12. LLM評価：自然な文章を、明示したrubricで測る

    同じ意味でも言い方は何通りもあるため、模範解答との文字一致だけでは文章を正しく採点できない。そこで評価したい条件を並べたrubric（採点基準表）を用意し、何を良い回答とするかを先に定義する。この節では、従来の自動指標とLLM-as-a-Judgeの長所・偏りを比べる。

    評価法は回答品質をそれぞれ別の信号で近似する。次の表は、実際に観測するものと、見落としやすい失敗を並べる。

    方法見ているもの主な限界
    BLEU / ROUGE / METEOR模範解答との語句の重なり意味が正しくても表現が違う回答を低く採点し得る
    LLM-as-a-Judgeprompt、回答、rubricを読んだ総合判断提示順・長さ・model系列による偏り
    人手による校正一部sampleを人が採点し、judgeとの不一致を確認高costで、評価者間にもばらつきがある

    Position biasは先または後に提示された回答を選びやすい偏り、verbosity biasは長い回答を高く評価しやすい偏り、self-enhancement biasはjudgeと同じmodel系列の回答を高く評価しやすい偏りである。表から得る結論は「judge LLMが人間を不要にする」ではない。候補順の入替え、明確なrubric、二値判定、人手校正を組み合わせ、知識・推論・coding・安全性など複数軸を測る。

    13. 非textへ進む問い：Transformerは文字専用なのか

    self-attentionが扱うのは文字そのものではなく、数値vectorの列である。それなら画像も小さな領域に分けてvectorへ変換すれば、同じ仕組みで領域同士の関係を学べる。この発想からVision Transformerへ進む。

    Inductive biasは、dataを見る前からarchitectureへ組み込まれた「こういう関係を重視するとよい」という仮定である。CNNは近接する画素を重視する強い局所性を持つ。一方、ViTは最初から近所だけを特別扱いせず、十分なdataから領域間の関係を学ぶ。この意味でViTは局所性に関するinductive biasが比較的弱い。

    14. Vision Transformer：画像をpatch token列として分類する

    ViT（Vision Transformer）は、画像を小さな正方形のpatchへ分割し、それぞれを文章のtokenのように扱う。手順は、①画像をP×P画素のpatchに分ける、②各patchのRGB値を一本のvectorへ並べる、③位置情報とCLS tokenを加える、④Transformer encoderへ通す、⑤最後のCLS表現から画像classを予測する、という順になる。

    x ∈ RH×W×C,　N = HW/P²,　z0=[xcls;xp1E;…;xpNE]+Epos,　ŷ=Head(zL0)H/W/C = 高さ・幅・RGB channel、P = patchの辺、N = patch数、xp = flattenしたpatch、E = 学習する線形射影、xcls = 集約用token、Epos = 位置embedding、zL0 = L層後のCLS表現、ŷ = 予測class。

    CLS tokenは、列全体の情報を集約するため先頭に追加する特別なtokenである。全patchとattentionした最後のCLS表現を分類headへ渡すと、「teddy bear」などのclassを予測できる。ViTはCNNのような強い局所性を持たないため、少ないdataでは不利になり得る一方、大量の画像からより自由に関係を学べる。

    15. VLM：画像tokenとtext tokenを、回答生成へ結ぶ

    VLM（Vision-Language Model／視覚言語model）は、画像の内容と文章を同時に扱うmodelである。ViTのようなvision encoderで画像をvector列へ変換し、それをLLMのtext tokenと接続すれば、「何が写っている？」という質問へ文章で答えられる。

    画像表現とtextをどこで融合するかには複数案がある。次の表は、講義で示された二方式を融合位置で見分けるためのものだ。

    入力列へ連結画像vectorをtext tokenと同じ次元へ変換し、同じ入力列へ並べるLLaVA型
    Cross-attentiontext側のQueryが、別に保持した画像表現をKey/Valueとして参照するLlama 3論文の例

    16. 自己回帰生成の制約：trainingとinferenceを取り違えない

    ARM（Autoregressive Model／自己回帰model）は、すでに生成したtokenを条件に次の1 tokenを決める。「A」まで決まってから「teddy」を選び、「A teddy」を見て次の「bear」を選ぶ、という順序である。前のtokenが決まるまで次へ進めないため、生成時の待ち時間が長くなりやすい。

    p(x1:T) = Πt=1T p(xt | x<t)Πは各位置の確率をすべて掛け合わせる記号。x1:T = 全token列、t = 現在位置、x<t = それ以前のtoken。この式は「左側を条件に次tokenの確率を出す」処理を最後まで繰り返すことを表す。

    学習時は正解の文章全体が分かっているため、未来tokenを見えなくするcausal maskを使いながら複数位置を並列計算できる。ところが推論時は、まだ生成していないtokenを先に使えない。したがってARM全体が並列化不能なのではなく、生成時のforward pass（modelを1回実行して次tokenの確率を得る処理）がtokenごとに連鎖することがlatencyを生む。この制約がdiffusion-based LLMの研究動機になる。

    17. 画像diffusion：noiseから目的分布へ戻る直観

    Diffusion model（拡散model）は、学習画像へ少しずつ砂嵐のような乱れを加え、その逆向きに乱れを取り除く方法を学ぶ。画像の各画素は連続した数値なので、正規分布から作るランダムな揺らぎであるGaussian noiseを段階的に加えられる。

    講義の要点。Forward processはclean imageへ徐々にnoiseを加え、reverse processは現在の画像に含まれるnoiseを推定して取り除く。目標は、無作為なnoiseから「自然画像らしい画像の集合」であるtarget image distributionへ戻る変換を学ぶことだ。

    補足。q(xt|xt−1)は一段階noiseを加えるforward過程、pθ(xt−1|xt)はmodelが学ぶreverse過程を表す。tはnoiseの段階、θは学習するparameterである。講義は直観を説明したもので、厳密なDDPM損失まで述べたわけではない。

    次節では、連続したnoiseを離散的なtext tokenへそのまま足せないため、noiseに相当するものをMASKへ置き換える。

    18. Masked Diffusion Model：離散tokenを全体から磨く

    文字tokenは画素のような連続値ではなく、「このtokenか、別のtokenか」という飛び飛びの値である。そこでMDM（Masked Diffusion Model）はGaussian noiseの代わりに、tokenを伏せるMASKを使う。学習では正しい文を徐々にMASKし、逆向きにはMASKされた位置の元tokenを復元する。

    flowchart LR A[正しいtoken列]-->B[forward: 徐々にMASK] B-->C[全MASK] C-->D[reverse: 一部を復元] D-->E[反復して完成文]

    図をクリックすると拡大できます。

    図が示すのは、MDMが左から右へ一語ずつ書くのでなく、文全体の複数箇所を反復して埋めることだ。質問などのprompt部分は伏せず、生成内容を決める条件（conditioning）として固定し、回答領域だけをMASKから復元する。MDMやDLLMという呼び方・記号は研究間でまだ統一されていない、と講師は注意した。

    19. Diffusion LLMの期待と未解決点：速度は品質と交換する

    MDMは複数位置を同時に更新できる可能性があるが、反復回数を減らしすぎれば品質が落ちる。この節では、自己回帰LLMと拡散型LLMを同じ軸で比べ、「新方式だから常に優れる」という誤解を避ける。

    20. Cross-pollination：modalityが成功した概念を交換する

    Cross-pollination（分野間の発想移植）とは、画像・文章・音声など異なるmodality（情報の種類）で成功した方法を相互に応用することだ。Transformerはtextから画像へ、diffusionは画像からtextへ移り、位置情報の与え方もmodalityに合わせて拡張されている。

    OCR（Optical Character Recognition／光学文字認識）は画像内の文字をtextへ変換する技術である。講師はDeepSeek-OCRを、少数のvision token（画像内容を圧縮した数値表現）から多くのtext tokenを復元する例として挙げた。またtext用RoPEは、画像では横位置と縦位置の両方を扱う2D座標へ拡張できる。重要なのは名称を移すことでなく、どの情報をどのvector列へ変換するかである。

    21. 基礎設計は未確定：optimizerから層数まで再び問い直す

    「Transformerを使う」と決めても、parameterの更新方法、層内の数値を安定させる方法、どの部分をtokenごとに動かすかには複数の選択肢がある。この節では、完成済みに見える基礎設計も研究対象であることを整理する。

    22. Data品質：学習の「燃料」が合成文で痩せる問題

    architectureを改善しても、偏ったdataで学習すればmodelの出力も偏る。この節では、Webから無選別に集める方法から、品質と多様性を選別するdata curationへ移る理由と、生成dataを繰り返し学ぶmodel collapseの懸念を説明する。

    Mid-trainingは、汎用pretrainingと用途別fine-tuningの間で、比較的大規模かつ高品質なcorpusを追加学習する段階である。講義はdata量だけでなく、専門性・信頼性・多様性を選別する重要性が増したと説明する。

    Model collapseは、modelが作った低多様性のtextを次世代modelが繰り返し学ぶと、元dataの稀な特徴が失われ、出力分布が痩せていく懸念を指す。講師の「検索結果の80%がLLM生成かもしれない」という数字は問題規模を伝える口頭例であり、厳密な統計としては扱わない。dataを整えても、推論を提供できるcostでなければ社会へ届かないため、次節はqualityとcostの同時最適化へ進む。

    23. Quality / cost Pareto frontier：最高点から、提供可能な最適解へ

    利用者にとって重要なのは最高得点のmodelだけでなく、必要な品質を払える価格と待てる時間で得ることだ。この節では、品質、価格、latency（応答までの待ち時間）を同時に比べるPareto frontierを説明する。

    Pareto frontierは、「他方を悪化させずには、品質もcostもこれ以上改善できない候補」の境界である。たとえば同じ費用で品質80のmodel Aと品質85のmodel Bがあれば、Aを選ぶ理由はなく、Aは候補から外れる。このように明確に劣る点を除いた外側の境界がPareto frontierになる。

    この見方では、SLM（Small Language Model）も「能力が低い縮小版」ではなく、taskに十分な品質を低cost・低latencyで出す候補になる。講義は最上位modelの提供者でさえ高額planで赤字になり得るという話を挙げ、研究競争が最高scoreだけでなく、持続可能な推論へ移ると見る。次節は、このfrontierを物理層から動かすhardwareへ進む。

    24. Hardware最適化：計算よりdata移動が高いなら、置き場所を変える

    計算を速くするには、式だけでなくデータが置かれた物理的な場所も考える。qualityとcostのfrontierを押し広げるには、model側の工夫だけでは足りない。FlashAttentionで見たmemory movementの問題へ戻り、KVを保存する場所とattention演算を近づける研究を読む。

    GPUはmatrix multiplication（行列の掛け算）に強いが、autoregressive生成では過去tokenのK/Vを繰り返し読み出す。このdata入出力がbottleneckなら、memory cell内または近傍でdot product（対応する数を掛けて合計し、QueryとKeyの似ている度合いを測る計算）を処理するanalog in-memory computingに利点が生まれる。analogとは、連続的な電圧・電荷・pulseなどの物理量を演算に使う方式である。

    講義が紹介した研究は、特定のsimulation条件でH100と比べ、遅延を最大約1/100、演算当たりenergyを最大約1/70,000にできる可能性を推定した。これは汎用実機が常にその倍率で高速という意味ではない。図は回路を暗記するためでなく、model architectureがhardware設計を逆に規定し始めたことを示している。

    26. Agentの民主化と安全性：stepが増えるほど失敗は累積する

    複数の作業を自動でつなぐと、一つの失敗が最終結果まで届く可能性が増える。現在の用途から次に予想されるのは、技術者だけでなく誰もが自然言語でagentic workflowを組み、browserやOSまで操作させる世界である。この節では可能性と、権限を持つagent特有のriskを同じ流れで説明する。

    P(少なくとも1 step失敗) = 1 − (1 − p)nPは確率、pは1 stepの失敗確率、nはstep数。各stepが独立で同じ失敗率だと仮定した説明用の式である。たとえばp=1%、n=10なら、少なくとも1回失敗する確率は約9.6%になる。実際のagentでは失敗が互いに影響するため、この式は直観を示す簡略例である。

    Browser agentは、webページ内に埋め込まれた命令を正規の指示と誤認するprompt injection（外部contentによる指示の乗っ取り）や、閲覧できる秘密情報を外部へ送るdata exfiltration（情報の不正持ち出し）の危険を持つ。講師はChatGPT Atlasを当時の例として挙げ、将来は安全性を示す証明書のような仕組みも必要かもしれないと展望する。

    ほかにも、利用中の経験を継続的に学ぶcontinual learning、利用者ごとに振る舞いを変えるpersonalizationとprivacyの両立、内部判断を説明するinterpretability、そして安全性は未解決である。Hallucinationは、根拠がない、または事実と異なる内容をもっともらしく生成する現象で、次token予測が事実検証そのものを目的にしていない設計とも関係する。

    用語ミニ索引

    • embedding：tokenや画像patchの意味・特徴を、多数の数を並べたvectorで表したもの。
    • logit：各候補tokenへmodelが付ける、確率へ変換する前の生の点数。
    • causal mask：生成位置から未来tokenが見えないよう、attentionを遮る仕組み。
    • CLS token：BERTやViTで、列全体の情報を集約するため先頭へ加える特別なtoken。
    • cross-attention：一方の列がQueryを出し、別の列をKey/Valueとして参照するattention。
    • HBM / SRAM：大容量だが転送が比較的遅いGPU memory / 小容量だがchip内で高速なmemory。
    • rollout：promptを受けてmodelが最後まで生成した回答全体。
    • advantage：得られた報酬が比較基準よりどれだけ良いか、または悪いかを示す量。
    • conditioning：prompt、画像、既知tokenなどを、生成内容を決める条件として与えること。
    • model collapse：多様性の低い生成dataを繰り返し学び、稀な表現や特徴が失われていく懸念。
    • groundedness：回答中の主張を、提示資料や確認可能な出典で裏付けられる度合い。

    1. この最終回で、何をつなげて学ぶのか

    最初に確かめるのは、「Lecture 9 は新しい用語を増やす回ではなく、これまで学んだ部品をどんな順で結び直す回なのか」である。まだ前の節はないので、まずこのガイド全体の地図を置く。以後の節では、文章を扱う基本のしくみから始め、画像、生成方法、実運用の順に進む。先に地図を持つと、途中で出る技術が「何のための部品か」を見失いにくい。

    ここでいう大規模言語モデル（Large Language Model、LLM）は、大量の文章から次に来そうな文字列の単位を予測するよう学んだ計算モデルである。料理にたとえるなら、LLM は一皿を丸ごと暗記するのではなく、「この材料の後には何を置くと自然か」という多数の組合せを覚えた料理人に近い。Transformerは、その料理人が文章の離れた部分どうしを見比べるための基本設計である。講義の後半で扱う画像やagent（LLM が道具を使いながら作業を進める仕組み）も、この設計を別の問題へ広げたものとして読む。

    まず開始スライドでは、最終回が「復習、現在の傾向、締めくくり」の三部からなることを確認してほしい。登壇者名や講義名だけでなく、単一の新手法ではなく全体像を扱う回だという位置づけに注目する。

    2. 文章を数に変え、必要な言葉を参照するしくみ

    §1 の地図を受けて、まず問い直すのは、「人にはそのまま読める文章を、モデルはどんな単位に分け、どの言葉を手掛かりに意味をつかむのか」である。§1 の地図で最初に置いた「情報を数列にする」工程を具体化する。後で画像の patch を token として扱うためにも、まず文章の token が単語と同じではないことを理解しておく。

    トークン（token）は、モデルが一度に扱う文字列の区切りである。日本語では「今日」「は」「晴れ」「です」のような語や文字のまとまりに、英語では語全体や語の一部に分かれることがある。サブワード分割器（subword tokenizer）は、単語を再利用しやすい部品へ分ける道具だ。例えば unhappiness を un、happi、ness に分ければ、初めて見る語でも既知の部品から扱える。これは、すべての完成品を倉庫に置く代わりに、共通の部品で多くの製品を組み立てる方法に似ている。ただし、区切り方が悪いと日本語の一語が多数の token になり、費用や入力長に影響する。

    次のスライドでは、テディベアの短い文が「分割する → 数にする → 文中の別の場所を参照する」という連鎖の共通例として繰り返し使われている点を見てほしい。矢印や専門語を暗記するより、同じ文の中で各段階が何を受け取るかを追う。

    図の要点は、token 化は意味理解の終わりではなく入口だということだ。分けた token は埋め込み（embedding）、すなわち特徴を表す多数の数の並びへ変換される。たとえば「銀行」と「川岸」のように同じ綴りでも文脈で意味が変わる語を扱うには、単語帳のように一つの固定ベクトルを置くだけでは足りない。ここで各位置が文中のほかの位置を読める仕組みが必要になる。

    固定の単語帳から、文脈を読む仕組みへ

    word2vecは、近くに現れる語を予測して単語のベクトルを学ぶ代表的な方法である。しかし同じ語には同じ表現を与えやすく、文脈ごとの違いを作りにくい。再帰型ニューラルネットワーク（Recurrent Neural Network、RNN）は、左から順に読み、途中までのメモである隠れ状態（hidden state）へ情報を渡す方法である。長い文では最初の情報が薄れ、遠い語を直接見直しにくく、順番待ちのため並列計算もしにくい。この二つの弱点を解くのが自己注意機構（self-attention）である。自己注意機構は、各 token が同じ文の中から必要な token を選んで読む仕組みで、付箋を付けた資料から必要なページだけを引く作業にたとえられる。

    次の式を見る前に、三つの役割を決める。Query（Q、探したい内容を書く質問札）、Key（K、その質問札と照合する見出し札）、Value（V、実際に受け取る本文）である。「その は何を指すか」を読む位置なら、Q は「指示語の参照先を探したい」という質問札、各名詞の K は見出し札、各名詞が持つ情報が V になる。式は、① Q とすべての K の近さを比べる、② 数が極端にならないよう縮める、③ 比率に直す、④ その比率で V を集める、という四段階を一行に縮めたものとして読む。

    小さな例では、「クマは本を読んだ。それは面白かった」の二文目で、それ の Q が「本」の K と強く合えば、「本」の V に大きな重みが付く。他の語を完全に捨てるのではなく、重みの合計を 1 にして配分するのがポイントである。次の数式では、どの記号がどの段階を表すかに注目してほしい。

    Attention(Q,K,V) = softmax(QKᵀ / √dk) V① QKᵀ：各 Query と各 Key の内積を取り、「どれくらい関係がありそうか」の表を作る。② √dk で割る：Key の次元数 dk が大きいほど内積も大きくなりやすいため、点数が一つへ極端に集中しないよう整える。③ softmax：各 Query ごとの点数を、合計 1 の重みへ変える。④ V を掛ける：重みの大きい Value を多く受け取る。Q = 質問札、K = 見出し札、V = 本文、T は転置を表す。

    式の後半で V に掛かる重みが変わると、受け取る文脈も変わる。Q と特定の K が強く合えば、その V の比率は大きくなる。逆に dk を考慮せず点数が大きくなりすぎると、softmax が一つの候補だけを過信しやすい。自己注意機構は遠い語を一度で直接参照できる反面、語順そのものはまだ知らない。次節では「どの順番で並ぶか」と、長い文を生成するときの記憶の節約を加える。

    補足（本レポートの説明）。 token 数は文字数や単語数と一致しない。日本語、記号、URL、珍しい固有名詞では分割が細かくなることがあるため、API の入力上限や料金を見積もるときは実際の tokenizer で数えるのが安全である。この実務上の注意は、講義の基礎説明を補うものだ。

    3. 語順を伝え、長い文章を効率よく読むしくみ

    §2 の仕組みを一歩進めるために確認するのは、「§2 の自己注意機構は、同じ単語が並んだ文でも、どの順番で置かれたかと長い会話の過去をどう扱うのか」である。自己注意機構は必要な場所を選べるが、位置を渡さなければ「犬が人を追う」と「人が犬を追う」の違いを知る手掛かりがない。そこで位置情報と生成時の記憶を足し、目的に応じた Transformer の使い分けへつなぐ。

    位置表現（positional encoding）は、列の何番目にいるかをベクトルへ知らせる印である。RoPE（Rotary Position Embedding、回転位置埋め込み）は、位置ごとに Query と Key の数値を異なる角度へ回す方法だ。ここで「回す」は画面の文字を回転することではなく、ベクトルの座標を数学的に変換することを指す。時計の針が時刻ごとに異なる向きを持つように、Q と K の照合結果へ位置の差を織り込める。近い語と遠い語を同じようには扱いたくない問題を解くが、非常に長い位置へ外挿したときの振る舞いは、学習方法や実装に依存する。

    次の図では、RoPE が token 本体へ単純に番号札を足すのではなく、Q と K を位置に応じて変えてから照合することを見てほしい。行列が難しく見えても、「位置の違いが Q と K の相性に現れる」という一点を押さえればよい。

    図から分かるのは、attention が語の意味だけでなく相対的な距離も使えるようになることだ。次に必要なのは、生成済みの長い列を毎回読み直さない工夫である。attention headは、関係を読む独立した小さな視点で、ある head は主語と動詞、別の head は指示語と参照先のように異なる手掛かりを拾える。

    Key/Value キャッシュ（KV cache）は、すでに生成した token の K と V を保存する記憶である。次の token を出すたびに過去全体の K/V を作り直さずに済むため、会話履歴が増える生成で有効だ。ただし、保存する token が増えるほどメモリを使う。グループ化 Query 注意機構（Grouped-Query Attention、GQA）は、複数の Q 用 head に K/V 用 head を共有させる設計である。全員に別々の資料棚を持たせず、数人で同じ棚を使うような節約で、KV cache を小さくできる。その代わり、共有を強めすぎると head ごとの見方の自由度は下がりうる。

    次の表では、「どちら向きの token を見られるか」と「何を出力したいか」を対応させて読む。表にあるencoderは入力全体を読んで表現を作る側、decoderは左側の生成済み token を見ながら続きを作る側である。BERT、GPT、T5 は固有名ではなく、この見え方の違いを表す代表例として見る。

    形式読む範囲主な仕事
    Encoder-only（BERT）両方向分類・embedding
    Decoder-only（GPT）左側のみ次token生成
    Encoder–decoder（T5）入力全体＋生成途中入力を別textへ変換

    表の結論は優劣ではない。文章を分類したいなら両側を読める encoder が便利で、続きを生成したいなら未来を見ない decoder が必要になる。GQA と KV cache は特に後者の待ち時間とメモリに効く。次節では、モデル全体を毎回同じように動かすのではなく、token ごとに専門部分を選ぶという、さらに大きな計算節約へ進む。

    4. MoEで大きなモデルの一部だけを動かし、temperatureで次のtokenの選び方を調整する

    §3 の効率化の続きで、分けて考えたいのは二つの問いである。混ぜてはいけない。問いAは「大きなモデルの中で、今回の token にどの部分を計算させるか」、問いBは「計算後に出た候補から次の token をどの程度ランダムに選ぶか」である。§3 では一つの Transformer を効率よく読む方法を見た。ここでは、複数の専門部品から一部を選ぶMoEと、候補の選ばれ方の散らばりを決めるtemperatureを、別々の問題として学ぶ。

    Mixture of Experts（MoE、専門家の混合）は、Transformer のフィードフォワードネットワーク（Feed-Forward Network、FFN）を複数のexpert（専門ネットワーク）へ分け、token ごとに一部だけ使う設計である。通常のDense モデルでは、入力 token はその層の FFN 全体を通る。MoE ではgate（振り分け器）が「この token にはどの expert が役立ちそうか」を点数化し、上位だけへ送る。これは会社の全員に毎回同じ問い合わせを配る代わりに、受付が二人の担当者だけへ回す仕組みに似ている。モデル全体のパラメータ数を増やしながら、毎 token で実行する有効パラメータ（active parameters）を抑えるのが狙いである。単に「規模を使わない」と言うと、保存するパラメータを減らすのか、実行する部分を減らすのかが区別できない。MoE が正確に行うのは後者である。

    次の図では、token が全 expert へ同報されるのではなく、gate から選ばれた経路だけを通る点を見てほしい。expert の箱が多いことと、毎回すべてが動くことは別だと意識する。

    図から読み取る要点は、MoE がモデルの知識量そのものを魔法のように無料にする技術ではないことだ。gate の計算、expert 間の通信、特定 expert への仕事の偏りは残る。たとえば 8 人の expert を用意し Top-2、すなわち上位 2 人を選ぶ設定なら、各 token で主に動く expert は 8 人中 2 人である。残り 6 人の FFN はその token には実行しないが、別の token では選ばれうる。次に、同じモデルの出力候補をどう選ぶかという別問題を扱う。

    数式を読む目的は、MoE の振り分けと temperature の確率調整が同じ操作ではないと確認することだ。まず MoE の式では、入力 x を選ばれた expert の変換へ通し、gate の重みで混ぜる。次に temperature の式では、モデルがすでに出したlogit（ロジット、確率に変える前の候補点） z を確率へ変える。具体例として候補の logit が [4, 2, 1] なら、低い T は 4 の候補を強く選びやすくし、高い T は 2 や 1 の候補にも機会を与える。前者は expert の数を一人も変えず、後者はパラメータの一つも増減させない。

    問いA：どの expert を実行するか（MoE）
    MoE: y = Σe∈Top-k ge(x) fe(x)
    y = MoE 層から出る最終の表現、x = 入力 token の表現、e = expert の番号、fe(x) = expert e の変換結果、ge(x) = gate が付ける重み、Σ = 選ばれた expert の結果を足し合わせる記号、Top-k = 実際に動かす上位 k 個。8 experts の Top-2 なら、和に入るのは選ばれた 2 expert だけである。
    問いB：次の token をどのくらい散らして選ぶか（temperature）
    これは MoE の routing とは無関係で、同じ logit から作る確率分布を調整する操作である。
    Temperature: pi(T)=exp(zi/T)/Σjexp(zj/T)
    i = 今見ている候補、j = 比べる全候補の番号、pi(T) = 候補 i を選ぶ確率、zi = その候補の logit、T = temperature、exp = 点数を正の重みに変える関数、Σ = 全候補の重みの合計。T を下げると点数差が強調され、上げると分布が平らになる。

    k を 2 から 1 に下げれば、MoE はさらに少ない expert しか動かさず計算を節約するが、複数専門家を混ぜる余地は減る。tokenを確率分布からsamplingする場合、T を低くすれば出力は安定しやすいが、同じ誤りを繰り返すことがある。T を高くすれば多様な候補を試せるが、もっともらしくない token も増える。最大logitのtokenを常に選ぶgreedy decodingでは、正のTを変えても候補順位は変わらない。また数式上のT=0は未定義なので、実装では「samplingせず最大候補を選ぶ」特別指定として扱われることが多い。つまり k はモデル内部の計算経路、T はsampling時の探索の強さを決める別のつまみである。次節では、モデルを大きくするだけでなく、どれだけデータと計算を与えるかも一緒に決める必要を見る。

    補足（本レポートの説明）。 MoE の「総パラメータ数」と「有効パラメータ数」を同じ数字として比べると誤解しやすい。前者は保存される expert 全体の大きさ、後者は一 token の計算で選ばれる部分である。通信量やバッチの偏りも実際の速度に影響するため、Top-k だけで提供コストは決まらない。

    5. モデルの大きさ・学習データ・計算量をどう釣り合わせるか

    MoE で大きさと実行量を分けた次に尋ねるのは、「§4 のように大きなモデルを用意したとき、パラメータ数だけを増やせば性能は伸びるのか」である。答えは否で、十分な練習問題と練習時間がなければ大きな器を使い切れない。そこで、モデルの大きさ、読ませるデータ量、学習に使える計算量を同時に考えるスケーリング則（scaling law）を使う。

    パラメータ（parameter）は、学習によって調整されるモデル内部の数値のつまみである。学習 token 数は、訓練中に読ませた文字列単位の合計で、同じ文を何度読むかも含む。計算量（compute）は、それらの token を通し重みを更新するための演算予算である。スケーリング則は、これらを変えた実験でテスト損失（test loss、未知データへの予測の外れ具合）がどう変わるかを観測した経験的な関係であって、自然法則ではない。大きいモデルに少ないデータしか与えない学習不足（undertraining）を避ける問題を解くが、データ品質や構造が変われば比率も変わる。

    次の図では、縦軸の test loss が低いほどよいこと、横方向に一つの量だけを増やす曲線ではなく、限られた計算予算で data と parameter をどう配るかを見てほしい。「右へ行くほど常に勝つ」と読まないことが重要である。

    図から読み取る要点は、固定予算なら巨大モデルへ偏らせるより、モデルとデータを釣り合わせた点がよくなりうることだ。これを計算最適（compute-optimal）な学習と呼ぶ。次の簡潔な式は、講義で紹介された目安を数字の大きさまで読み下すために置く。

    式の N はパラメータ数、D は学習 token 数で、20 は「一パラメータ当たり約 20 token」という係数である。例えば N = 100B の B は billion（10 億）なので、100B は 1,000 億パラメータを表す。式に入れると D ≈ 2,000B、すなわち2T、2 兆 tokenになる。これは足し算の公式ではなく、ある時点の研究結果から得た「まず疑うためのものさし」である。式を見るときは、20 倍がいつでも正解だと思わず、何を固定した実験かを意識してほしい。

    D ≈ 20ND = 学習 token 数、N = パラメータ数。講義が紹介した歴史的な rule of thumb（経験的な目安）では、100B（1,000億）parameter なら約 2T（2兆）token を読む。係数 20 は、特定のモデル構造・データ品質・tokenizer・計算予算で観測された比率であり、普遍的な法則ではない。

    N を大きくして D を増やさなければ、モデルは表現力を十分に学べず学習不足になりうる。逆に D を増やしても N や計算予算が小さければ、すべてのパターンを取り込めない。さらに「20」はデータの重複、品質、目標タスク、訓練手順で動く。規模を正しく配分しても、実行時にデータをメモリへ運ぶ時間が支配的なら遅いままである。次節ではその物理的な詰まりを減らす FlashAttention を見る。

    6. 同じ attention を速く動かすには、何を減らすのか

    規模の配分を見た後に確かめるのは、「§5 で釣り合わせた大規模学習を、なぜ演算回数だけ見ても速くできないのか」である。attention は多くの数を掛け合わせるが、GPU では数を計算器へ運ぶ時間も支配的になりうる。そこで計算の答えを変えずに、メモリとの往復を減らすFlashAttentionと、複数 GPU へ仕事を分ける方法を学ぶ。

    HBM（High Bandwidth Memory）は GPU の外側に近い大容量メモリ、SRAM（Static Random-Access Memory）はチップ内部にある小容量だが高速なメモリである。机の横の小さな引き出しと、部屋の向こうの大きな書庫を想像するとよい。FlashAttentionは、巨大な attention 行列を HBM に何度も書き戻す代わりに、小さなブロック（block）を SRAM に載せて処理し、必要な中間値は工夫して再計算する実装方法だ。これは attention を近似する技術ではなく、同じ結果をより少ない入出力で得ることを狙う。

    次の図では、HBM が「大きいが遠い」、SRAM が「小さいが近い」と描かれている関係を見てほしい。重要なのは、演算器の速さより、二つの記憶領域を何回往復するかという矢印である。

    図から読み取る要点は、少し再計算が増えても HBM への読み書きが大きく減れば全体が速くなる場合があることだ。このようにデータ移動を意識する設計をI/O-awareと呼ぶ。FLOPは浮動小数点演算の回数、ボトルネック（bottleneck）は全体の速度を最も遅い部分として制限する箇所である。FLOP が少ないことと、実時間が短いことは同義ではない。

    複数 GPU には、何を分けるのか

    データ並列（data parallelism）は、異なる学習例を複数 GPU へ配り、各 GPU が同じモデルの複製で計算して最後に更新量を合わせる方法である。モデル並列（model parallelism）は、一つのモデル自体を複数 GPU に分割して、一つの入力を協力して通す方法である。前者は生徒をクラスごとに分けて同じ教材を解く形、後者は一冊の大きすぎる本を章ごとに分けて読む形に近い。どちらも通信が必要で、GPU を増やせば無条件に速くなるわけではない。

    講義の要点。 FlashAttention、KV cache、GQA、MoE はすべて「モデルの理論上の能力を保ちながら、どこでメモリ・通信・演算を使うか」を動かす技術である。速さを議論するときは、token 数、バッチサイズ、文脈長、GPU 間通信を固定せずに数字だけ比べないことが重要になる。

    計算を回せるようになっても、何を学ばせるかは別問題である。次節は、基礎知識、指示への応答、好ましい振る舞いを一つのデータで混ぜず、三段階に分ける理由を説明する。

    7. 基礎知識、指示への応答、好ましい振る舞いをどう分けて学ぶか

    計算の速さを見た次に、教材の役割として問うのは、「§6 の計算資源を使ってモデルを学習するとき、なぜ一種類の教材だけで済ませず段階を分けるのか」である。大量の文章を読むこと、質問に答える形を覚えること、人の好みに合う答えを選ぶことは、似て見えて異なる仕事だ。役割を分けると、次節の RLHF がどこに入るかも分かる。

    事前学習（pretraining）は、大量の text や code を使い、次の token を当てる練習で言語・知識・形式の土台を作る段階である。教師あり微調整（Supervised Fine-Tuning、SFT）は、「質問」と「望ましい回答」の組を使って、指示に従う出力形式を教える段階である。選好調整（preference tuning）は、二つの回答のどちらを人が好むかという比較を使い、有用さ、安全さ、文体などを整える段階である。本をたくさん読んで語彙を得る、模範解答を見て問題への答え方を学ぶ、添削でよりよい伝え方を覚える、という三段階にたとえられる。

    次の図では、初期化されたモデルから三つの段階が直列に並び、それぞれで与える信号が違うことを見てほしい。「後ろの段階が前を捨てる」のではなく、前の能力の上へ別の目的を重ねる図である。

    図から読み取る要点は、pretraining が会話用アシスタントを完成させるわけではなく、SFT だけが好ましくない選択肢を比較して下げるわけでもない、という役割分担だ。次に表で、各段階の教材と出力の変化を照合する。表の略称を丸暗記せず、「どんな採点信号があるか」を読む。

    8. 人の「こちらがよい」を、モデルの学習へどう戻すか

    三段階の最後へ進む前に問うのは、「§7 の選好調整で、人が二つの回答を比べた判断を、次の token を選ぶモデルへどう伝えるのか」である。人は「この回答は 0.73 点」と絶対点を付けるより、「A より B がよい」と比較するほうが判断しやすい。その比較を報酬へ変える人間のフィードバックによる強化学習（Reinforcement Learning from Human Feedback、RLHF）を、まず言葉の対応から読む。

    強化学習（reinforcement learning）は、行動の結果に付く点数を手掛かりに、よい行動を選びやすくする学習方法である。LLM では方策（policy）が「今までの文章から次の token をどの確率で選ぶか」という規則、状態（state）が prompt と生成済み token、行動（action）が次の token、報酬（reward）が完成した回答への評価になる。ロボットが一歩ずつ動く代わりに、LLM は一語ずつ文章を作り、完成後にまとめて評価を受ける。途中の token に最後の評価をどう割り振るかが難しさである。

    次の図では、LLM と強化学習の用語を一対一に対応させている点を見てほしい。特に「一回の回答」が多数の token 行動の連鎖であり、評価が最後に来ることに注目する。

    図から読み取る要点は、LLM を人間のような意思主体だと主張することではなく、確率的な次 token 選択を学習問題として扱う見方だ。人の比較をたくさん集めたら、報酬モデル（reward model）、すなわち回答へ一つの評価点を付ける別モデルを学習できる。Bradley–Terry modelは、その二つの評価点の差が大きいほど高い方を選ぶ確率も高くなる、と表す比較のモデルである。

    次の式は「絶対的に正しい点」を出すためではなく、同じ prompt への二回答のどちらが好まれやすいかを確率で表すために必要になる。y_i と y_j は二つの回答、r_i と r_j は報酬モデルの点である。例えば r_i = 2、r_j = 0 なら、i の重みは j よりかなり大きくなり、i が選ばれる確率は直感的にはおよそ 9 割に近づく。差が 0 なら五分五分、差を広げるほど高い側へ寄る、と読む。

    P(yi ≻ yj) = exp(ri) / (exp(ri)+exp(rj))yi, yj = 同一 prompt への二応答、≻ = 前者を好む、r = 報酬モデルが出す scalar（単一の数値）score、exp = 数値を正の重みに変える関数。分子は i の重み、分母は二回答の重みの合計なので、結果は 0〜1 の確率になる。

    r_i を上げる、または r_j を下げると、i を好む確率は上がる。だが報酬モデルの点を無制限に追わせると、内容をよくする代わりに採点器の癖だけを突く報酬ハッキング（reward hacking）が起こりうる。そこでKL ダイバージェンス（KL divergence）という、二つの確率分布のずれを測る量で、SFT 後の参照モデルから急に離れすぎないよう罰点を付ける。PPO（Proximal Policy Optimization）はさらに一度の更新幅を切り詰めるclippingを使う代表的な方法である。次節では、人の好みではなく、数学や code の正誤を自動で確かめられる場合へ進む。

    補足（本レポートの説明）。 Bradley–Terry の score は「真の品質を物差しで測った値」ではない。比較データに現れた傾向を並び順へ写すための内部尺度であり、評価者、prompt、候補集合が変われば校正も変わりうる。

    9. 正解を確かめられる問題で、推論のしかたをどう育てるか

    人の選好から自動判定へ移すときに問うのは、「§8 で人の好みを報酬にした方法を、正誤を自動で判定できる数学や code の問題へどう使うのか」である。最終回答の前に途中の考えを書く推論連鎖（reasoning chain / Chain of Thought）を出すと、モデルは一発で答えるより多くの計算を使える。しかし長い文章が正しいとは限らないため、検証と学習の基準が必要になる。

    検証可能な報酬（verifiable reward）は、答えの一致やテストの通過のように、あらかじめ決めた規則で正誤を判定できる点数である。これは「説明が親切か」のような主観的な評価とは違う。PPOではcritic（価値モデル、value model）が「ここまで書いたら最終報酬はどれくらいになりそうか」を予測し、その予測と実際の差を使う。GRPO（Group Relative Policy Optimization）では、同じ問題へ複数の回答を出し、その集団内の平均を比較基準にするため、別の critic を省ける。問題の難しさごとに絶対点を比べるのでなく、同じ問題の別解どうしを比べる工夫である。

    次の図では、推論連鎖を含む回答を採点して学ぶ流れと、PPO が value model を持つ一方で GRPO は回答群を使う違いを見てほしい。図の目的は「どちらが万能か」ではなく、比較基準をどこから得るかを見分けることだ。

    図から読み取る要点は、GRPO が数学そのものを理解する追加部品ではなく、良い回答を相対的に増やす更新方法だということだ。ここでbaseline（比較基準）は通常どれくらいの報酬かという目安、advantage（優位度）は実際の報酬がその目安より上か下かを表す。次の式は、その上下を群の中で同じ尺度にするために使う。

    式は三段階で読む。① 同一 prompt から G 個の回答を作り、それぞれの報酬 r_i を得る。② mean(r)、つまり群平均を引いて、平均よりよいか悪いかの符号を出す。③ std(r)、報酬のばらつきで割り、群ごとの尺度をそろえる。例えば 4 回答の報酬が [1, 0, 0, 0] なら平均は 0.25 で、正解の 1 本は平均より上、三つの誤答は平均より下になる。標準偏差まで含めると正答はおよそ正の +1.73、各誤答は負の -0.58 となり、正答側を増やし、誤答側を減らす方向の信号になる。

    Ai = (ri − mean(r)) / std(r)Ai = i 番目の回答の advantage、ri = その回答の報酬、mean(r) = 同じ prompt から作った回答群の平均報酬、std(r) = 群内の報酬のばらつき。平均より高ければ Ai は正、低ければ負になり、0 に近ければ更新の根拠が弱い。

    正答が増えて平均が上がれば、同じ報酬 1 でも advantage は小さくなり、「簡単な問題での当たり」を過大評価しにくい。一方、全回答の報酬が同じなら std(r)=0 となり、表示した式はそのままでは0除算で未定義になる。実装では分母へ小さな値εを足す、または全advantageを0として更新信号を出さないなどの処理を行う。標準偏差が非常に小さい群でも値が不安定になりうる。回答の長さによって更新が偏る問題も報告され、講義は DAPO や GRPO Done Right を修正研究として紹介した。次節では、モデルの内部記憶ではなく最新資料を取りに行く RAG を扱う。

    10. 最新資料や社内資料を、回答の前にどう読ませるか

    推論を育てた後に現れる知識の問いは、「§9 のように推論を上達させても、学習後に変わったニュースや非公開の社内文書をどう参照するのか」である。モデルの重みには学習時点までの傾向しか入らない。そこで回答の直前に関連資料を探して渡す検索拡張生成（Retrieval-Augmented Generation、RAG）を使う。

    知識の締切（knowledge cutoff）は、学習データが反映している時点の限界である。RAG の検索（retrieval）は、質問と資料を検索用のベクトルにし、近い候補を取り出す工程である。これは本棚全体を会話欄へ貼るのでなく、まず索引で候補の棚を絞る作業に似ている。次に再順位付け（reranking）で、質問と候補を詳しく比べ、本当に役立つ数件だけを prompt へ入れる。重みを再学習せず、外部知識を回答条件として渡す問題を解くが、検索が外れれば流暢な回答でも根拠は外れる。

    次の図では、質問から候補取得、再順位付け、上位文書を prompt に加えるまでが別工程になっている点を見てほしい。「検索結果を一件貼るだけ」とは違う流れである。

    図から読み取る要点は、RAG の品質が最後の LLM だけで決まらないことだ。bi-encoderは質問と文書を別々にベクトル化し、大量候補から高速に近いものを拾う方法である。cross-encoderは質問と一文書を同時に読み、より細かく関連度を付ける方法で、再順位付けに使われる。この二段構えは速さと精度の両立を狙うが、cross-encoder を全資料へ使うと遅くなる。

    RAG を一回の回答として追う

    1. 資料を小さな断片へ分け、各断片の検索用ベクトルと出典を保存する。
    2. 質問を同じ空間のベクトルにし、近い断片を広めに取得する。
    3. 質問と候補を詳しく比べて順位を付け、少数の本文と出典を選ぶ。
    4. 選んだ本文を「根拠」として prompt に添え、LLM に根拠の範囲で答えさせる。

    この手順でも、資料の分割が悪い、必要資料が検索漏れする、古い版と新しい版が混ざる、LLM が渡された本文を読み違える、といった失敗は残る。したがって回答には出典を示し、検索結果が十分かを確認する設計が必要になる。RAG は外部世界を読む経路である。次節では、予約や検索 API のような道具を使う経路へ進む。

    11. 外部の道具を安全に使い、結果を受け取るしくみ

    資料を読む RAG の次に問うのは、「§10 の RAG が資料を読むだけなのに対し、検索、計算、予約、データベース更新のような外部操作をどう扱うのか」である。文章を返すだけの LLM は現実の状態を変えない。そこで、LLM が必要な道具を選び、別のプログラムが実行して結果を戻すtool callingと、その反復を行うagentを分けて考える。

    tool callingは、LLM が「この操作を、この引数で呼びたい」という構造化された要求を出す仕組みである。toolは検索 API、電卓、予定表、社内システムなど、決められた入力を受け取り結果を返す機能を指す。agentは、観測し、次の行動を選び、結果を見てまた行動するループを持つシステムである。LLM が直接ネットワークや口座を自由に操作するのではなく、実行を仲介する層が必要なのが肝心である。

    次の図では、LLM の「tool を使いたい」という出力と、仲介層の「検証してから実行する」仕事を分けて見てほしい。結果が LLM へ戻り、必要なら次の行動を選び直す矢印が agent の特徴である。

    図から読み取る要点は、tool の結果を読むことも次の判断の材料になるという点だ。仲介層はスキーマ（schema）、すなわち引数名、データ型、必須項目、許される値を定めた入力契約に照らして要求を検証する。例えば日付が必須の予約 tool へ文字だけを送らない、読み取り専用 tool に更新命令を渡さない、といった境界を作る。これは LLM の出力がもっともらしくても、そのまま正しい API 呼び出しだとは限らない問題を解く。

    2. LLM が必要なら tool 名と引数を構造化して選ぶ。

    12. 自由な回答を、どんな基準で公平に評価するか

    道具を使えるようにした次に問うのは、「§11 の agent が出した回答や操作を、模範解答との文字一致だけに頼らず、何を基準に評価すればよいか」である。同じ意味のよい答えにも多くの言い方があるため、文章の表面だけを比べると見誤る。まず、何をよいとするかを先に言葉で決めるrubric（採点基準表）を置く。

    評価指標（metric）は、出力の望ましさを数や判定へ写す物差しである。BLEU、ROUGE、METEORは参照文との語句の重なりを測る代表的な自動指標で、定型的な翻訳や要約の比較に役立つ。しかし意味が正しくても表現が違えば低くなりうる。LLM-as-a-Judgeは、prompt、モデル回答、rubric を別の LLM に読ませ、理由と score を出させる評価方法である。幅広い文章を読める利点があるが、判定役も偏りや誤りを持つ。

    次の図では、Judge に回答だけでなく criteria、すなわち具体的な採点観点を渡し、score の前に理由を出させる構造を見てほしい。Judge が万能な真実判定器として描かれていないかを意識する。

    図から読み取る要点は、rubric を明示すると「簡潔さ」「根拠」「安全性」のどれを見た score なのかを後から点検しやすいことだ。次の表では、各評価法が実際に何を観測しているかと、どんな誤りを見落とすかを比べる。数値の高低だけでなく、物差しの死角を読む。

    13. Transformer は文字以外の情報も扱えるのか

    文章の評価から視覚へ広げる前に問うのは、「§12 まで文章の回答を評価してきた Transformer を、画像のように文字ではない情報へそのまま広げられるのか」である。§2 で見た通り、Transformer が直接読むのは文字そのものではなくベクトルの列である。画像も小さな領域を数列へ変えれば同じ計算へ渡せるが、画像には近くの画素が関係しやすいという性質がある。そこで、何を最初から仮定するかを考える。

    モダリティ（modality）は、文章、画像、音声のような情報の種類である。帰納バイアス（inductive bias）は、データを見る前からモデル設計に埋め込む「この種類の関係を重視するとよい」という仮定を指す。例えば畳み込みニューラルネットワーク（Convolutional Neural Network、CNN）は、近くの画素を同じ小さなフィルタで繰り返し見るため、「近い場所には関連する模様がある」という強い局所性の仮定を持つ。写真の目や輪郭は隣り合う画素でできるので、少ない画像でも学びやすいことがある。

    Vision Transformer（ViT）は、画像を patch の列にし、最初から近所だけを特別扱いせず attention で関係を学ぶ。これは、都市の近所だけをまず見る CNN と、最初から地図上のどの二地点も結べる Transformer の違いにたとえられる。ViT は遠く離れた領域の関係を扱いやすい一方、局所性という助けが弱いので、データが少ない条件では不利になりうる。次節では、この「画像を token 列にする」実装を一枚ずつ追う。

    補足（本レポートの説明）。 inductive bias が強いことは古い、弱いことは常に優れている、という意味ではない。データ量、画像の種類、計算予算に応じて、あらかじめ与える仮定とデータから学ばせる範囲の交換がある。講義の ViT 導入はその比較を考える入口である。

    14. 画像を小さな token の列にして分類する ViT

    ViT の考えを具体化するために見るのは、「§13 の ViT は、縦横に並ぶ画像をどの順で Transformer が読める token 列へ変え、最後に一つの分類名を出すのか」である。画像の全画素を一気に一語として扱うと細部を失い、画素を一つずつ token にすると長すぎる。そこで小さな正方形の patch をちょうどよい単位にする。

    ViT（Vision Transformer）は画像をpatch（小さな正方形の切れ端）へ分け、各 patch を文章の token のように扱うモデルである。画像の高さを H、幅を W、色 channel 数を C とする。通常の RGB 画像なら C は赤・緑・青の 3 である。patch の一辺を P、patch の枚数を N とする。CLS tokenは、列全体の情報を集約して最後に分類へ渡すため、先頭へ足す特別な token である。これは各 patch の代表者が最後に一つの報告書へまとめる役に近い。

    次の図では、画像が patch の格子に切られ、位置情報と CLS token が加わってから encoder へ入る順を見てほしい。最終的な「teddy bear」という label は、一つの patch だけを見て決めるのでなく、CLS token が全 patch から集めた情報で決める。

    図から読み取る要点は、patch を並べただけでは左上か右下かを区別できないため、位置埋め込みも必要なことだ。次の式は、画像サイズから N を数え、patch を埋め込みへ変え、CLS 表現から予測を出す四段階をまとめたものになる。

    式を左から読む。① x ∈ RH×W×C は画像が H×W 個の位置と C 色成分を持つこと。② N = HW/P² は、HとWがPで割り切れる場合に、画像を P×P patch へ切った枚数を表す。割り切れない画像は、端へ余白を足すpaddingや一部を切るcroppingで大きさを調整する。具体例として 224×224 の RGB 画像を 16×16 patch にすると、縦 14 枚、横 14 枚なので 14×14 = 196 patch になる。③ 各 patch の画素を一列にして線形射影 E で token の次元へそろえ、CLS と位置埋め込みを足す。④ L 層の encoder を通った先頭の CLS 表現を分類 head へ渡し、予測 ŷ を得る。次の式では、記号を工程順に追ってほしい。

    x ∈ RH×W×C,　N = HW/P²,　z0=[xcls;xp1E;…;xpNE]+Epos,　ŷ=Head(zL0)R = 実数値の並びの集合、H = 高さ、W = 幅、C = 色 channel 数、P = patch の一辺、N = patch 数。xp = 一列にした patch、E = patch を token 次元へ写す学習済みの線形射影、xcls = 集約用 CLS token、Epos = 位置埋め込み、L = encoder の層数、zL0 = L 層後の先頭 token、Head = class を決める分類部、ŷ = 予測 class。セミコロンは token を列へ連結することを表す。

    H や W を大きくする、または P を小さくすると N は増える。たとえば patch を 16 から 8 に半分にすると、縦横の枚数は二倍ずつになり、token 数は四倍になるため、細部は見やすくなる一方で attention の計算とメモリは重くなる。P を大きくすると逆の交換が起きる。ViT は大量データから自由な関係を学べる可能性があるが、分類名を一つ返すだけでは画像について会話できない。次節では画像 token と text token を結び、文章で答える VLM へ進む。

    15. 画像と文章を結び、質問に文章で答える VLM

    分類から会話へ進めるときに問うのは、「§14 の ViT が画像を一つの class に分類できても、『この画像で何が起きているか』へ文章で答えるには何を足すのか」である。画像の特徴を text の生成器へ渡せば、分類ラベルで止まらず、質問に応じて説明できる。これが視覚言語モデル（Vision-Language Model、VLM）の基本の考え方である。

    vision encoderは画像を patch ベクトルの列に変える部品で、ViT が代表例である。言語モデル（LLM）は text token の列から続きを生成する部品である。両者の数の幅や意味空間はそのままでは合わないため、projector（射影器）という変換層で画像表現を LLM が受け取れる形へそろえる。写真を理解する目と、言葉で話す口を翻訳係でつなぐような構造だ。画像と質問が必要な部分だけを結び付ける問題を解く一方、画像内の小さな文字、数え上げ、空間関係は依然として難しいことがある。

    次の図では、テディベア画像と質問が同時に入って、固定 class ではなく短い自然言語の回答が出ることを見てほしい。画像だけから答えるのでなく、質問が「何について答えるか」を絞る条件になっている。

    図から読み取る要点は、同じ画像でも質問が変われば違う文章を返せる点だ。接続方法には、画像 token を text token と同じ列へ並べる方法と、text 側が画像を必要なときに参照する方法がある。次の表では、両者の「どこで融合するか」を見比べる。

    表に出るcross-attentionは、一方の列が Query を出し、別の列を Key と Value として読む attention である。§2 の Q/K/V を思い出せば、質問文の token が「画像のどこを見ればよいか」という Q を出し、画像特徴の K/V を参照すると理解できる。入力列への連結は、画像を先に text token と同じ列へ並べ、通常の attention に任せる方法である。

    16. 一語ずつ生成する方式は、なぜ待ち時間が長くなるのか

    画像も扱える生成器が文章を出すとき、問い直すのは、「§15 の VLM を含む多くの LLM が文章を出すとき、なぜ GPU があっても次の token を待ちながら進むのか」である。自己回帰モデル（Autoregressive Model、ARM）は、すでに決まった左側の token を条件に、次の一つを選ぶ方式だ。便利で成熟した方法だが、未生成の未来を先に使えないという順序制約がある。

    因果的（causal）とは、現在の出力が未来の token を見てはいけないという制約である。例えば三 token の文「猫 が 寝る」なら、最初は「猫」を選び、次に「猫」を見て「が」を選び、最後に「猫 が」を見て「寝る」を選ぶ。推論時（inference）は未知の文章を実際に生成する時点、学習時（training）は正解の文章全体をすでに持ち、予測の誤差から重みを更新する時点である。この二つを混同しないことが、並列化の話を正しく読む鍵になる。

    次の図では、BOS（文頭を表す特別な印）から token が一つずつ増え、次の forward pass が前の出力を待つ矢印を見てほしい。図は「モデル内部の計算が全く並列化できない」と言っているのではなく、完成前の token を次の入力にできないことを示す。

    図から読み取る要点は、出力が長いほど待つ生成 step が増えることだ。次の確率の式は、一文全体の確率を「その時点より左が分かっている条件付き確率」の掛け算へ分けて書く。Π（パイ）は足し算の Σ と違い、並んだ項をすべて掛ける記号である。

    式の x1:T は最初から T 番目までの token 列、xt は t 番目の token、x<t はそれより左の token を表す。先の「猫 が 寝る」なら、全体の確率は p(猫) × p(が | 猫) × p(寝る | 猫 が) と読む。各項は「前までが決まったとき、この次が来る確率」なので、推論時は二項目を計算するまで三項目の入力が完成しない。次の式では、この分解と Π の位置を見てほしい。

    p(x1:T) = Πt=1T p(xt | x<t)Π = t=1 から T までの確率をすべて掛ける記号。x1:T = 全 token 列、xt = 現在位置の token、x<t = それ以前の token、縦棒 | = 「…を条件として」を表す。各項は左側だけを見て次 token を選ぶ確率である。

    T、つまり出力 token 数が増えるほど、推論時に必要な逐次 step は増える。学習時には正解列をあらかじめ持つため、causal mask、すなわち各位置から未来を見えなくする覆いを掛けながら、多くの位置を同時に計算できる。推論時だけは未知の token を埋める必要がある。この待ち時間を別の生成順で減らせないか、という問いが次節の画像 diffusion、さらにその後の text への応用につながる。

    17. 画像をノイズから少しずつ復元する diffusion とは何か

    逐次生成の待ちを見た後に問うのは、「§16 の一語ずつ待つ生成とは別に、画像ではどのように新しい絵を作る方法が成功してきたのか」である。画像の画素は連続した数値なので、きれいな画像を徐々に乱し、その逆を学ぶ拡散モデル（diffusion model）が使える。次節で text へ発想を移す前に、まず画像で何をしているかを直感的に分ける。

    画素（pixel）は画像を構成する小さな点で、RGB の強さのような連続値を持つ。ガウス雑音（Gaussian noise）は、平均の周りへランダムに揺れる連続的なノイズで、テレビの砂嵐のように見える。forward processは元画像へ少しずつ雑音を足して最終的にほぼランダムな状態へ近づける過程、reverse processは今ある雑音を予測して少しずつ除く過程である。真っ白な大理石から彫刻を削り出すのではなく、砂嵐から不要な成分を何度も取り除いて写真らしい分布へ戻す、と考えるとよい。

    次の図では、「ノイズは作りやすい」「逆向きの変換を学ぶ」「数学的に段階を定義できる」という三点を見てほしい。完成画像を一回で当てる図ではなく、途中状態を何回も改善する図である。

    図から読み取る要点は、ランダムな出発点から自然画像らしい集合へ戻る変換を学ぶことだ。学習では本物の画像に既知の量の雑音を加え、モデルに「今入っている雑音」または「少し前のよりきれいな状態」を予測させる。生成では純粋な雑音から始め、学習した逆向きの変換を繰り返す。途中の形を修正できる利点がある一方、反復回数が多ければ速さは失われ、各 step の誤差が積み上がる。

    補足（本レポートの説明）。 q(xt|xt−1) は一段階ノイズを加える forward 過程、pθ(xt−1|xt) はモデルが学ぶ reverse 過程を表す。t は雑音の段階、θ は学習するパラメータである。講義はこの直観を中心に扱っており、ここで厳密な DDPM の損失式を導入しているわけではない。

    画像のように連続値なら雑音を少量ずつ足せる。しかし text の token は「この語か別の語か」という離散的な選択で、同じ雑音をそのまま足せない。次節では雑音の役を MASK、つまり伏せ字に置き換える。

    18. 伏せ字を全体から埋め直す、text 用の拡散モデル

    画像の雑音除去を文章へ移すときに問うのは、「§17 の連続的な画像ノイズを、飛び飛びの値である text token へどう置き換えるのか」である。文字列の token は 0.2 だけ「猫」にする、といった連続的な混ぜ方ができない。そこで、内容を隠すMASKをノイズの代わりにし、隠した位置を反復して復元するMasked Diffusion Model（MDM）を考える。

    MASK tokenは「ここに何かがあるが、何かはまだ伏せる」という特別な印である。MDM の学習では正しい token 列の一部を MASK に置き換え、モデルが周囲の文脈から元の token を予測する。生成では回答領域を多くの MASK から始め、一部を埋め、残りを見直しながら完成させる。クロスワードの空欄を左から一つずつ埋めるのではなく、分かる箇所を同時に書き込み、全体を何度も見直す作業に近い。逐次生成の待ちを減らせる可能性があるが、どの空欄をいつ確定するかという新しい難しさが生まれる。

    次の図では、回答領域が全 MASK から始まり、A teddy bear is reading のような列へ変わる過程を見てほしい。質問などの条件部分まで消すのではなく、残しておく点が重要である。

    図から読み取る要点は、複数の位置を同時に候補化できることだ。conditioning（条件付け）は、prompt、画像、すでに確定した token のように、生成内容を決めるため残しておく情報である。MDM は条件部分を固定し、回答部分だけを復元する。次のフローでは、学習時の「隠す向き」と生成時の「埋める向き」を対にして追ってほしい。

    19. 拡散型 LLM は、どこで速くなり、何が未解決なのか

    MDM の可能性を見た後で比べるのは、「§18 の MDM は複数の空欄を扱えるとして、成熟した自己回帰モデルより実際に何がよくなり、何を失うのか」である。新しい生成順は自動的な勝利ではない。ここでは拡散型 LLMを、出力順、モデルを呼ぶ回数、得意な編集、品質という同じ軸で自己回帰モデルと比べる。

    反復 stepは、MASK の予測と確定を一回行う単位である。自己回帰モデルは出力 token 数にほぼ対応する回数だけ順番に進むのに対し、MDM は設定した反復 step ごとに複数位置を更新できる可能性がある。fill-in-the-middleは、前と後ろが分かっている中央の欠落を埋める作業で、たとえば既存コードの関数の途中だけを補う用途である。両側を見ながら埋めやすいことは MDM の魅力だが、生成過程を細かく制御する方法や、複雑な reasoning を安定して行う方法は発展途上である。

    20. 画像・文章・音声のあいだで、成功した発想はどう移るか

    二つの生成法を比べた次に問うのは、「§19 の拡散型 LLM のように、ある情報形式でうまくいった方法を別の形式へ持ち込むとき、何をそのまま移し、何を作り替えるのか」である。単に流行語を輸入するのではなく、表現、位置、生成順という問題を別のモダリティへ写し替えるcross-pollination（分野間の発想移植）として考える。

    §13 で定義したモダリティは情報の種類である。Transformer は text token の関係を読む設計から画像 patch の関係を読む ViT へ広がった。逆に diffusion は画像の連続ノイズ除去から text の MASK 復元へ広がった。移植の核心は名前ではなく、「何を token の列にし、どの位置情報を与え、どの条件を固定するか」をその形式に合わせて決め直すことだ。似た形に見えても、画像の二次元位置と文章の一次元の語順は同じではない。

    次の図では、Transformer が text から vision へ、diffusion が vision から text へ渡っている矢印を見てほしい。二つのトピックを別々に覚えるのでなく、片方の成功がもう片方の制約を問い直す循環として読む。

    21. Transformer の設計は、どこまで決まっていてどこが未解決か

    新しい分野へ移した後に戻って問うのは、「§20 のように新しいモダリティへ広げる前に、そもそも Transformer の中身は完成した定番なのか」である。答えはそうではない。文章、画像、効率を支える部品には複数の選択肢があり、目的・データ・hardware が変わればよい組合せも変わる。ここでは設計を部品表としてではなく、何を調整しているかとして見る。

    アーキテクチャ（architecture）は、層、attention、FFN、正規化などをどう組み合わせるかというモデルの骨組みである。optimizer（最適化手法）は、誤差を小さくする方向を示すgradient（勾配）から、各 parameter をどれだけ動かすかを決める更新規則である。normalization（正規化）は層内の数値の大きさを整え、学習が不安定になりにくくする部品、activation（活性化関数）は単純な直線の組合せだけでは表せない曲がりを加える部品である。どれも見えにくいが、長い学習が壊れず進むかを左右する。

    次の図では、optimizer、normalization、attention の共有方法、FFN、層数が並んでいることを見てほしい。Kimi K2 や MuonClip は「これが唯一の標準」という証明ではなく、基礎部品も研究対象だという講義の例である。

    22. 学習データを、量だけでなく質と多様性でどう選ぶか

    設計の選択を見た次に問うのは、「§21 でアーキテクチャを工夫しても、学習に使う文章や画像が偏っていたら何が起きるのか」である。モデルは教材に含まれるパターンを学ぶため、無選別に大量収集するだけでは信頼性、専門性、多様性を保証できない。そこでデータ選別（data curation）と、合成データを重ねたときのmodel collapseを分けて考える。

    コーパス（corpus）は学習に使う文書やコードなどの集合である。data curation は、重複、低品質、誤情報、望ましくない内容を減らし、目的に合う資料を選び、出典や多様性を点検する作業を指す。食材をトラック一台分そのまま鍋へ入れるのでなく、傷んだものを除き、献立に必要な品目をそろえる作業に近い。mid-trainingは、広い基礎学習と用途別の微調整の間に、比較的大規模で高品質な資料を追加して学ばせる段階である。専門分野へ寄せる問題を解くが、狭い資料に寄せすぎると汎用性を失う可能性がある。

    次の図では、無選別の web scrape から curation へ関心が移り、pretraining と fine-tuning の間に mid-training を置く流れを見てほしい。右側の model collapse は、量の不足ではなく分布の多様性が痩せる懸念を表している。

    図から読み取る要点は、よいデータとは単に「人間が書いたデータ」ではなく、目的に対して信頼でき、多様で、重複や汚染を点検できるデータだということだ。合成データ（synthetic data）はモデルが生成した教材で、検証可能な code や数学の答えを増やすなど有用な場合もある。問題は、低多様性の出力を検証せず繰り返し次世代の教材にすると、まれな表現や端の事例が徐々に落ちることにある。

    model collapseは、生成物を再帰的に学習することで元のデータ分布の細かな特徴が失われ、出力が似通っていく懸念を指す。講義内の「検索結果の 80% が LLM 生成かもしれない」という表現は問題意識を示す口頭例であり、ここでは厳密な統計値として扱わない。対策は生成データを一律禁止することではなく、出典の追跡、品質検証、人間・一次資料との混合、長い尾の事例の監視を行うことだ。データを整えても提供コストが高すぎれば使えない。次節は品質と価格を同時に比べる Pareto frontier を説明する。

    23. 最高性能だけでなく、品質・価格・待ち時間をどう選ぶか

    高品質なデータを考えた後に問うのは、「§22 でよいデータから高性能なモデルを作れても、利用者が実際に使える形で提供するには何を比べるべきか」である。最高 score の一モデルだけを見ると、料金や待ち時間を見落とす。そこでPareto frontier（パレート最前線）を使い、同じ品質なら安い候補、同じ費用なら高品質な候補を残す。

    品質（quality）は task に対する正確さや評価 score、コスト（cost）は一回答や一定 token 数に必要な料金・計算資源、レイテンシ（latency）は要求から応答までの待ち時間である。ある候補が別の候補より同じか高いコストで、品質が同じか低く、少なくとも一方で明確に劣るなら、その候補は支配される（dominated）といい、Pareto frontierには残らない。安い代わりに品質も低い候補はtrade-offを持つため、用途によってfrontierに残り得る。これは一つの万能な一位を決める方法ではなく、交換を隠さず候補を絞る方法である。

    次の図では、散布図の外側にある frontier と、内側で他に明確に負けている点を見分けてほしい。縦の performance だけでなく横の cost を同時に追うのが読み方である。

    図から読み取る要点は、frontier 上の複数候補には、それぞれ選ぶ理由が残ることだ。次に抽象的な語を具体化する。これは講義のモデル順位を再現する例ではなく、Pareto の読み方を示す仮想例である。

    具体例（本レポートの補足）。 仮にモデル A が 1,000 回答あたり 10 円で品質 80、モデル B が同じ 10 円で品質 85 なら、A は B に支配される。モデル C が 5 円で品質 82 なら、B より品質は少し低いが半額なので、用途によっては C も frontier に残る。即時の簡単な要約なら C、難しい契約レビューなら B という選び方がありうる。待ち時間を加えれば、二次元の線ではなく三つ以上の軸になる。

    小規模言語モデル（Small Language Model、SLM）は、単に能力が低い縮小版ではない。決まった社内分類、短い定型応答、端末内処理のように必要な品質が限定された task なら、低コスト・低レイテンシ・データを外へ出さない利点でよい候補になる。講義が最上位モデルの提供でも採算が課題になりうると述べる背景には、この運用上の交換がある。次節では frontier のコスト側を、model の式ではなく hardware の配置から動かす研究を見る。

    24. データを動かす代わりに、計算を近づける hardware の考え方

    コストを比べた後に問うのは、「§23 の品質・コストの交換を、モデルの縮小だけでなく、データが物理的にどこで計算されるかから改善できるか」である。§6 の FlashAttention で見た通り、生成では演算だけでなく KV cache の読み書きが遅さと電力を左右する。そこで memory の近くで attention を計算するanalog in-memory computingという研究を読む。

    GPUは多くの数を同時に掛けて足す行列積（matrix multiplication）が得意な計算装置である。自己回帰生成では過去 token のKV cacheを何度も読み、Query と Key の内積（dot product）、すなわち対応する数を掛けて合計する類似度計算を行う。in-memory computingは、このデータを遠い演算器へ運ぶ代わりに、保存場所の内部または近くで計算する考え方である。analogは 0 と 1 だけでなく、連続的な電圧、電荷、パルスなどの物理量で値を表して演算する方式を指す。

    次の図では、KV を専用の cell に置き、物理信号を使って attention の一部を計算する構成を見てほしい。回路記号を覚えるより、「読み出してから掛ける」の距離を短くしようとしている点に注目する。

    図から読み取る要点は、Transformer の計算パターンが hardware の設計課題を変え始めたことだ。講義で紹介された研究は、特定の simulation 条件で H100 と比べて遅延を最大約 1/100、演算当たりの energy を最大約 1/70,000 にできる可能性を推定した。ここでの「可能性」は、どの task、precision、メモリ容量、製造条件でも同じ倍率になるという製品保証ではない。

    analog 回路には、連続信号のノイズ、精度のばらつき、書き込み耐久性、既存 GPU ソフトウェアとの統合、汎用性といった課題がある。精度が必要な部分をデジタル計算へ戻せば、移動を減らした利点も変わる。したがってこの図は「GPU はすぐ不要になる」という結論ではなく、data movement がボトルネックなら演算場所を変える余地があるという研究の例である。次節では、こうした効率化が既にどんな日常の用途を支えているかを見る。

    25. 日常の仕事と学習で、LLM に任せる部分と確認する部分

    hardware を見た後に現実の仕事で問うのは、「§24 の効率化で LLM を使いやすくしても、実際の仕事ではどの作業を任せ、どの確認を残すべきか」である。講義は coding、会話支援、創作、学習を既に変化した用途として挙げる。ここでは便利さだけでなく、誤りがどこで影響するかを対にして読む。

    codingはプログラムを書く、読んで直す、テストする作業である。text-to-queryは自然言語の質問を SQL のような検索・集計命令へ変えること、conversational assistantは対話で情報整理や説明を行う支援役である。groundedness（根拠への接地）は、回答中の主張を提示資料や確認可能な出典で裏付けられる度合いを指す。これらは LLM が初稿や候補を早く出す問題を解くが、もっともらしい誤り、権限外の操作、出典なしの断定までは消さない。

    26. 自律的な agent を便利にしながら、安全をどう保つか

    日常用途から自律の問題へ進む際に問うのは、「§25 の日常用途から、複数の操作を自動でつなぐ agent へ進むと、なぜ便利さとともに失敗の危険も増えるのか」である。自然言語で workflow を作れるようになれば専門家以外も道具を組み合わせられる。しかし browser や OS の操作権限を持つほど、一つの誤認や外部の悪意ある指示の影響は大きくなる。

    agentic workflowは、目標を受け、情報を集め、tool を呼び、結果を見て次の step を決める一連の作業である。browser agentは web ページを読み、必要に応じてクリックや入力を行う agent を指す。講義が当時の例として挙げた ChatGPT Atlas は、こうした browser/OS 支援が広がる方向を示す。ここでの問題は単に「一 step が正しいか」ではなく、複数 step のうち一つでも重要な失敗があれば最終結果が崩れうることだ。

    次の図では、agentic workflow の民主化、browser や OS での支援、そして真に自律的な agent の安全性が同じ将来像の中に置かれている点を見てほしい。機能の宣伝と未解決の問いが併記されていることが重要である。

    図から読み取る要点は、能力の拡大と安全性を別々の後回しにできないことだ。次の式は、step 数が増えると少なくとも一度失敗する確率がどう増えるかを、分かりやすい仮定の下で表す。

    まず p は一 step が失敗する確率、n は step 数である。直接「少なくとも一回失敗」を数える代わりに、①一 step が成功する確率を 1-p とする、② n step すべてが成功する確率を (1-p)n とする、③それを 1 から引く、という順で読む。例えば p=1%、n=10 なら、全十 step が成功する確率は約 90.4%、少なくとも一回失敗する確率は約 9.6%になる。次の式では、この「全部成功」の余事象になっている構造を見てほしい。

    P(少なくとも1 step失敗) = 1 − (1 − p)nP = 求める確率、p = 1 step の失敗確率、n = step 数。p=1%、n=10 なら 1−0.9910 ≈ 0.096、すなわち約 9.6%。これは各 step が独立し、同じ失敗率だと仮定した説明用の式である。

    p を下げれば失敗確率は下がり、n を増やせば上がる。ただし実際の agent では step が独立とは限らない。最初の誤った検索結果が後の判断を連続して誤らせるなら失敗は相関し、逆に確認 step が前の誤りを検出するなら単純式より安全になる。式は正確な事故率を予言するものではなく、長い workflow に検証点、権限分離、停止・承認の境界が必要な理由を示す。

    prompt injectionは、web ページや文書に混ぜられた命令を、agent が信頼できる指示と取り違える攻撃である。data exfiltrationは、閲覧できた秘密情報を許可されない場所へ持ち出すことを指す。対策としては、外部コンテンツを命令として扱わない境界、最小権限、送信先の許可リスト、重要操作前の人の承認、実行記録が考えられる。さらに継続学習（continual learning）、個別化（personalization）と privacy、解釈可能性（interpretability）、hallucination（根拠なくもっともらしい誤情報を作る現象）は未解決の論点である。次節では、こうした変化の速い分野をどの順で学び、主張を確かめるかへ進む。

    27. 新しい主張を、論文・実装・評価条件でどう確かめるか

    安全性の未解決点を受けて問うのは、「§26 の未解決問題を前に、流行語や一枚の benchmark 図だけに振り回されず、何を順に学べばよいか」である。講義を読み終えた後に必要なのは、最新情報を無批判に追うことではなく、主張を一次資料と実装へ往復させる習慣だ。ここではその入口を、検証の順序として置く。

    一次資料（primary source）は、研究者の原論文、公式仕様、公式スライドのように主張の元になる資料である。再現可能性（reproducibility）は、他者がデータ、設定、コード、評価手順をたどって結果を確かめられる度合いである。benchmarkは同じ問題でモデルを比較する試験セットだが、score だけでは prompt、temperature、費用、評価者の差を隠す。§12 の評価バイアスを思い出し、結果を見る前に「何を比べ、何を固定したか」を聞く。

    28. 分からなくなったときに戻る、講義と用語の索引

    用語ミニ索引：一文の定義と、戻る場所

    • embedding（埋め込み）：token や画像 patch の特徴を表す数の並び。意味が近いものを近い表現にできる。まず §2、画像なら §14 へ戻る。
    • logit（ロジット）：次 token の確率へ変換する前にモデルが付ける生の点数。temperature がこの点数差をどう見せるかは §4。
    • KV cache：生成済み token の Key と Value を保存し、次 token で作り直さない記憶。長い会話でのメモリとの交換は §3 と §24。
    • causal mask：学習中でも未来 token を見えなくし、自己回帰の条件を守る覆い。学習と推論の違いは §16。
    • CLS token：ViT などで列全体の情報を集約するため先頭に置く特別な token。画像分類の流れは §14。
    • cross-attention：一方の列が Query を出し、別の列の Key/Value を読む仕組み。画像と言葉の接続は §15。
    • HBM / SRAM：大容量で比較的遠い GPU メモリと、小容量で高速なチップ内メモリ。data movement の問題は §6。
    • rollout：prompt を受けたモデルが最後まで生成した回答全体。複数 rollout を比べる GRPO は §9。
    • conditioning（条件付け）：prompt、画像、既知 token などを、生成内容を決めるため固定して与えること。MASK を埋める例は §18。
    • groundedness（根拠への接地）：回答が提示資料や確認可能な出典に裏付けられている度合い。RAG と実利用では §10、§25。
    • model collapse：低多様性の生成データを検証なしに繰り返し学び、まれな特徴が失われる懸念。データ選別の文脈は §22。
    • hallucination：根拠がない、または事実と異なる内容をもっともらしく生成する現象。外部資料、評価、人の確認を組み合わせる理由は §10、§12、§26。

    この索引の最後の問いは、「この語を知っているか」ではなく「この語がどの問題を解き、どの制約を残すか」である。そこで答えられなければ、該当節の図の前後、表の前後、数式の前後を読み直す。Lecture 9 の全体像は、個別技術を覚えた後に初めて具体的な設計判断へ使えるようになる。

    この節では、Lecture 2 全体の構成を示したうえで、前回扱ったSelf-attention、Query・Key・Value、Multi-head Attentionを短く復習し、この講義でどのTransformerの改良点とモデル系統を扱うのかを整理する。

    前提となる Lecture 1

    Self-attention、Q/K/V、Encoder–Decoder、scaled dot-product attention の導入は、先行レポート 「CME295 Lecture 1: Transformer」 で詳しく整理している。

    Self-attention と Multi-head の復習

    Attention(Q, K, V) = softmax(QKT / √dk)V

    各 head は独自の WQ/WK/WV で入力を射影し、Attention を並列計算する。head ごとの結果を連結し、WO で再びモデル次元へ射影する。講義は元論文の attention map を使い、異なる head が照応や構文関係を別々に捉え得ることを示す。

    公式研究による補足：Attention map の読み方

    QKT は raw score であり、通常「attention weight」と呼ぶのは scaling・mask・Softmax 後の値である。また可視化は関係を調べる手掛かりだが、モデル判断の因果的な説明と同一ではない。Jain & Wallace（NAACL 2019）は、attention weight だけを説明として扱うことへ注意を促している。

    2. なぜ位置情報が必要か

    この節では、Self-attentionだけでは語順を区別できない理由を確認し、tokenへ絶対位置を与えるLearned Position EmbeddingとSinusoidal Positional Encodingを比較する。さらにsin/cosの式の各記号、異なる周期を組み合わせる意味、相対距離を読み取れる仕組みを説明する。

    Self-attention は token 同士を直接結ぶため、RNN のような計算順序から位置を得られない。そこで token embedding に位置情報を注入する。

    方式仕組み長所制約
    Learned absolute位置ごとの埋め込み表を学習し、token embedding へ加算データから最適化できる表にない位置は直接扱えず、訓練長やデータの位置偏りに依存
    Sinusoidal位置と次元から sin/cos を計算し、token embedding へ加算追加パラメータ不要で任意位置の値を計算可能訓練長を超えた品質を保証せず、類似度は周期的
    PE(pos, 2i) = sin(pos / 100002i/dmodel)
    PE(pos, 2i+1) = cos(pos / 100002i/dmodel) Sinusoidal Positional Encoding。Vaswani et al. (2017), §3.5

    この式は何を計算しているのか

    これは、系列内の各 token に「何番目にあるか」を伝えるための Sinusoidal Positional Encoding（正弦波による位置エンコーディング）である。位置 pos ごとに長さ dmodel のベクトル PE(pos) をこの式で作り、同じ位置の token embedding に要素ごとに加算する。学習で値を覚える表ではなく、位置と次元から毎回計算する固定値なので、追加の学習パラメータはない。

    記号意味
    PEPositional Encoding。tokenの位置を表すために作るベクトル。
    pos系列内の位置番号。通常は先頭を0として、0, 1, 2, … と増える。
    dmodeltoken embedding と位置ベクトルの次元数。両者を加算するため同じ長さにする。
    i次元を2個ずつ選ぶ番号。2i 番目には sin、隣の 2i+1 番目には同じ周波数の cos を入れる。
    10000次元ごとの波長を短いものから長いものまで幾何級数的に広げるため、元論文で固定された基準値。
    直観：位置を複数の速さで動く「時計の針」に変える

    i=0 のペアは [sin(pos), cos(pos)] となり、位置が1進むたびに速く変化する。大きい i のペアほど分母が大きくなり、ゆっくり変化する。短い周期から長い周期まで多数の波を組み合わせることで、各位置は異なるパターンを持ち、モデルは近い位置と遠い位置の両方を区別する手掛かりを得る。pos=0 では、すべての sin 成分が0、cos 成分が1になる。

    sin と cos を同じ周波数のペアにする利点は、位置を一定量ずらす操作を、そのペアに対する線形変換として表せることにある。また、同じ周波数の2位置を比べると sin(a)sin(b) + cos(a)cos(b) = cos(a−b) となり、絶対位置 a と b から相対差 a−b に関する情報が現れる。これにより Attention は、token 自身の意味だけでなく「何個離れているか」も学習に利用できる。

    各次元は異なる周波数を持ち、低い次元側は速く、高い次元側はゆっくり変化する。元論文では learned と sinusoidal がほぼ同等だったため、長い位置にも式を適用できる可能性を理由に sinusoidal を採った。

    公式資料による精密化

    sinusoidal 値を訓練長より先で計算できることと、モデルがその長さへ正しく外挿できることは別である。また内積は相対距離の余弦和なので、同位置で最大になる一方、距離とともに単調減少するわけではなく周期的に振動する。

    3. T5 bias・ALiBi・RoPE

    この節では、位置ベクトルを入力へ足す方式から一歩進み、位置情報をAttention計算へ直接反映する3方式を扱う。T5 Relative Position Biasの学習可能な距離bucket、ALiBiの固定された線形ペナルティ、RoPEのQ/K回転を順に説明し、各方式が相対距離へどのような意味を与えるかを比較する。

    入力に位置ベクトルを足す代わりに、Attention の対応度を計算する場所へ位置を直接入れる方法が発展した。Relative Position Bias（相対位置バイアス）は、2つの token が何個離れているかに応じた値を、Softmax 前の Query–Key score（logit）へ加える方式である。T5 は似た距離を bucket にまとめ、その bucket ごとの加算値を学習する。

    ALiBi と RoPE を先にひとことで

    ALiBi（Attention with Linear Biases）は、遠い token ほど不利になる距離比例の値を Attention score から引く方式で、位置ベクトル自体は作らない。RoPE（Rotary Position Embedding）は、位置に応じて Query と Key のベクトルを回転させ、両者の内積に相対的な距離を反映する方式である。

    T5 Relative Position Bias：距離ごとの加点・減点を学ぶ

    T5 の方式は、tokenの表現そのものへ位置ベクトルを足さず、token i が token j をどれだけ参照するか決める Attention logit に、相対距離 j−i に応じた scalar（1個の数値）を加える。値が正ならその距離を参照しやすく、負なら参照しにくくなる。加算値は attention head ごとに学習されるため、近距離を重視するheadと遠距離を見るheadのような役割分担が可能になる。

    すべての距離へ別々の値を持つと表が大きくなるため、T5 は距離を bucket に分類する。近距離は1、2、3…のように細かく区別し、遠距離は対数的にまとめる。これにより「すぐ隣」と「2語先」は区別しつつ、非常に遠い距離は同じ種類として扱える。意味としては、内容の類似度だけで決めていたAttentionへ、相対的な近さ・遠さという学習可能な手掛かりを追加する方法である。

    scoreij = qi · kj / √dk + bbucket(j−i), head b が、相対距離bucketとheadごとに学習されるT5の位置bias。

    ALiBi：遠い位置へ線形ペナルティを与える

    ALiBi は Attention with Linear Biases の略で、Query と Key の距離が遠いほど大きくなるペナルティを、Softmax前のAttention logitから引く。学習する位置embeddingや距離表を持たず、headごとにあらかじめ決めた傾き mh を使う。傾きが大きいheadは近傍を強く優先し、傾きが小さいheadは遠方も比較的参照しやすい。

    scoreij,h = qi,h · kj,h / √dk − mh|i−j| 距離 |i−j| が大きいほどscoreを下げる。因果Attentionでは参照可能な過去位置に適用する。

    ALiBiが持つ意味は、モデルへ「一般に近いtokenほど関連しやすい」という単調な事前バイアスを直接与えることにある。式は学習時に見た系列長を超える位置でもそのまま計算できるため、長さ外挿を狙いやすい。ただし、式を適用できることと、未学習の長さで常に品質を維持できることは同じではない。

    方式Attentionへの反映学習相対距離の扱い
    T5 relative biaslogit に bucket 対応scalarを加算head別に学習近距離は細かく、遠距離は対数的にまとめ、最大距離以遠は同bucket
    ALiBihead別の傾き × 距離を logit から減算傾きは固定距離が遠いほど線形penalty。headごとに異なる受容範囲
    RoPEAttention 前に Q/K の次元ペアを回転角周波数は固定回転後の内積が相対位置 n−m の関数になる

    RoPE の直観

    RoPE（Rotary Position Embedding）は、Query と Key の数値を直接加減するのではなく、隣接する2次元ずつを位置に比例する角度で回転させる。位置0なら回転せず、位置が進むほど角度が変わるため、同じtoken表現でも置かれた位置によってQ/Kの向きが変わる。2次元の回転行列は次の形になる。

    R(θ) = [[cos θ, −sin θ], [sin θ, cos θ]]
    ⟨R(mθ)q, R(nθ)k⟩ = ⟨q, R((n−m)θ)k⟩ 絶対位置 m/n を入れた回転が、内積では相対差 n−m へ変わる。

    回転後のQとKの内積は、個々の絶対位置ではなく位置差 n−m に依存する。つまりRoPEは、「各tokenがどこにあるか」をQ/Kの向きへ埋め込み、Attention scoreを計算したときに「互いに何個離れているか」が現れるようにする。T5 biasやALiBiのようにscoreへ別の数値を足す方式ではなく、scoreを作るQ/Kそのものへ位置を組み込む点が違いである。

    高次元ではQ/Kを2次元ペアへ分け、ペアごとに異なる周波数で回転する。短い周期のペアは細かな位置差、長い周期のペアは大きな位置差を表す手掛かりになる。Value は回転しない。多くの近年モデルで採用されるが、RoPE の類似度も sin/cos から成るため単調な近接biasではなく、長さ外挿の品質は追加のスケーリングや訓練条件にも依存する。

    4. LayerNorm・Pre-Norm・RMSNorm

    この節では、深いTransformerの値と勾配を安定させる正規化について、LayerNormがhidden stateをどう整えるか、Post-NormとPre-Normで正規化を置く位置がどう違うか、RMSNormが何を省略して軽量化するかを、数式と構成図で比較する。

    深いTransformerでは、層を通るたびにhidden stateの値の大きさや分布が変わる。極端に大きい・小さい値が続くと勾配や最適化が不安定になりやすいため、各tokenのhidden stateを扱いやすいスケールへ整える normalization（正規化）を挟む。ここでは「どう正規化するか」と「sub-layerのどこで正規化するか」を分けて考える必要がある。

    LayerNorm：各tokenの特徴量を平均0・分散1相当に整える

    LayerNorm（Layer Normalization）は、1つのtokenが持つhidden stateの全特徴次元を対象に、平均 μ と分散 σ² を計算する。各値から平均を引き、標準偏差で割ることで中心とスケールをそろえた後、学習可能な γ（拡大率）と β（ずらす量）で必要な表現力を戻す。

    LayerNorm(x) = γ ⊙ (x − μ) / √(σ² + ε) + β μ と σ² は各tokenの特徴次元から計算し、ε は0除算を防ぐ小さな定数。

    例えばhidden sizeが768なら、各tokenについて768個の値から平均と分散を求める。別の文や別のtokenの統計には依存しないため、batch sizeや系列長が変わっても同じ方法で動作し、学習時と推論時の処理も同じである。目的は情報を消すことではなく、層へ入る値の尺度をそろえて最適化しやすくすることにある。

    Post-NormとPre-Norm：正規化を置く場所の違い

    Post-Norm（Post-LayerNorm）とPre-Norm（Pre-LayerNorm）は別の正規化計算ではなく、LayerNormをsub-layerとresidual connectionのどこへ配置するかという設計の違いである。ここで F はSelf-attentionまたはFFN、x はその入力を表す。

    Post-Norm

    LN(x + F(x))。Attention/FFNの出力へ元の入力を足してから正規化する。元TransformerとBERTの配置だが、非常に深いモデルではresidual経路にも正規化が入り、初期学習の勾配が不安定になりやすい。

    Pre-Norm

    x + F(LN(x))。先に入力を正規化してからAttention/FFNへ渡し、その結果を未加工のresidual経路へ加える。勾配が恒等経路を通りやすく、深いTransformerを比較的安定して学習しやすい。

    Pre-Normは学習安定性のため近年よく採用されるが、常に最終性能が高いとは限らない。また実装によっては最後にもう一度normalizationを置く。したがって「Pre-Norm」は正規化手法の名前ではなく、正規化の配置を表す言葉である。

    RMSNorm：平均を引かず大きさだけを整える

    RMSNorm（Root Mean Square Normalization）は、hidden stateの二乗平均平方根（RMS）で各値を割り、ベクトル全体の大きさをそろえる。LayerNormと異なり平均を引くre-centeringを行わず、通常は加算bias β も持たない。そのため計算がやや単純で、現代のLLMで広く使われる。

    RMSNorm(x) = g ⊙ x / √(mean(x²) + ε) g は学習可能な次元別scale。方向を大きく変えず、主にベクトルの大きさを整える。
    3語の関係

    LayerNormとRMSNormは「値をどう整えるか」の選択肢で、Pre-Normはそれらを「sub-layerの前に置く」という配置である。したがって、実際のモデルは「Pre-Norm構成でRMSNormを使う」のように両者を組み合わせられる。

    方式式の概略特徴
    Post-NormLN(x + F(x))元 Transformer と BERT。深いモデルでは初期勾配が不安定になりやすく、warm-upを要し得る。
    Pre-Normx + F(LN(x))Residual経路が直接残り、深いモデルの学習を安定させやすい。近年モデルで広く使われるが普遍ではない。
    RMSNormg ⊙ x / √(mean(x²)+ε)平均を引かず、βを持たず、RMSでスケールだけを整える軽量化。
    BatchNormbatch内の同一特徴を正規化batch統計に依存し、訓練/推論差が生じる。TransformerではLayerNorm系が一般的。
    補足：Internal Covariate Shift は確定した原因ではない

    講義では活性値の揺れを “internal covariate shift” と結び付ける。これは歴史的説明だが、Santurkar ら（NeurIPS 2018）は BatchNorm の効果を covariate shift の低減だけでは説明できず、最適化地形を滑らかにする効果を示した。LayerNormの有用性を単一原因へ還元しない方が正確である。

    5. Dense Attention の二乗コストと疎化

    この節では、通常のSelf-attention（Dense Attention）で文章が長くなると計算量とメモリ使用量が二乗で増える理由を確認する。続いて、参照先を近傍へ限定するSliding-window Attention、重要なtokenだけ全体を参照するglobal attention、両者を組み合わせるLongformerを説明し、層を重ねたときのreceptive fieldと疎な計算を高速化へつなげる実装上の要点まで扱う。

    長さ n の各 token が全 token を見ると、score 行列は n×n になる。Self-attention の主要計算は O(n²d)、score/weight 行列の保存は head ごとに O(n²) で、長文ほど負担が急増する。

    Longformer と sliding window

    Sliding-window Attentionは、各 token の参照先を系列全体ではなく前後の一定範囲（window）に限定する疎な Attention である。窓を token とともに滑らせることで、近隣の文脈を保ちながら全組み合わせの計算を避ける。

    • 各 token が近傍 w 個だけを見る sliding-window attention は O(nw)。
    • [CLS] や質問 token など g 個を global にすると、全体は概ね O(nw + ng)。
    • 実装では巨大なdense行列を作って後から消すのではなく、必要blockだけを計算する tiling / sparse kernel が重要。

    講義は、層ごとにlocalとglobalを交互に使う方式や、Mistralのように全層でwindowを使う方式を紹介する。後者では層を重ねるほど情報が伝播できる理論上の receptive field（受容野）、すなわち「ある上位層の表現へ間接的に影響し得る入力範囲」が広がる。ただし、受容野は各層が直接 Attention する範囲や、実際に有効活用できる context window と同じではない。

    6. MHA・MQA・GQA と KV cache

    この節では、自己回帰生成で大きなメモリ帯域を消費するKey/Valueをどこまで共有できるかを扱う。MHA、MQA、GQAのhead構成と品質・速度のトレードオフを比較し、過去tokenのKey/Valueを再利用するKV cacheの仕組みと容量への影響を説明する。

    Attention の別の効率化は、Query head の多様性を残しながら Key/Value head を共有すること。自己回帰Decoderは新tokenを生成するたびに過去のK/Vを再利用するため、K/Vのhead数がKV cacheの容量とmemory bandwidthへ直結する。

    前提：なぜ複数のAttention headを使うのか

    1つのAttentionは、入力から作ったQuery（何を探すか）とKey（何を持つか）の一致度で参照先を決め、対応するValue（取り出す情報）を混ぜる。複数headを使うと、あるheadは近くの構文、別のheadは遠い照応のように、異なる射影空間で複数の関係を並列に捉えられる。MHA・MQA・GQAの違いは、複数のQuery headを維持したまま、Key/Value headを何組用意するかにある。

    MHA：各Queryが専用のKey/Valueを持つ

    MHA（Multi-Head Attention）は、H 個のheadそれぞれに独立したQuery、Key、Valueの射影を用意する。例えば32 headなら、Q/K/Vをそれぞれ32組作る。各headが独自のK/V表現を持てるため表現容量は大きいが、自己回帰生成では過去tokenについて32組のK/Vをlayerごとに保存し、次のtokenを生成するたびに読み出す必要がある。

    MQA：すべてのQueryで1組のKey/Valueを共有する

    MQA（Multi-Query Attention）は、Query headをH 個残しながら、KeyとValueを全headで1組だけ共有する。各Queryは異なる「探し方」を維持するが、検索対象となるK/V表現は共通になる。MHAが32組のK/Vを持つ例ならMQAは1組だけなので、KV cacheの理論上の主要部分とその読込み量はおよそ1/32になる。

    decodeでは1 stepごとの計算量が小さくても、大きなKV cacheをGPUメモリから読む時間がボトルネックになり得る。MQAはこのmemory bandwidthを大幅に減らし、同じメモリで長いcontextや多い同時requestを扱いやすくする。一方、全Queryが同じK/Vを使うため、MHAより表現の自由度が下がり、モデルや学習条件によっては品質へ影響し得る。

    GQA：複数QueryのグループごとにKey/Valueを共有する

    GQA（Grouped-Query Attention）はMHAとMQAの中間で、H 個のQuery headをG グループへ分け、グループごとに1組のK/Vを共有する。例えばQueryが32 head、KVが8 headなら、4個のQuery headが1組のK/Vを共有する。MHAはG=H、MQAはG=1という両端の特殊ケースとして捉えられる。

    GQAはK/Vの種類を複数残すことでMQAより表現力を保ちつつ、MHAよりKV cacheを小さくする。上の32 Query / 8 KVの例では、KV cacheの主要部分はMHAのおよそ8/32 = 1/4になる。この品質と推論効率の折衷から、近年のDecoder-only LLMで採用されることが多い。

    覚え方

    Query head数を32とすると、MHAは「32人が各自の資料を持つ」、MQAは「32人が1冊の資料を共有する」、GQAは「数人ずつの班で1冊を共有する」構成である。共有を増やすほどK/Vの保存・読込みは減るが、各Query専用の情報表現は少なくなる。

    KV cache

    KV cache（Key–Value cache）は、自己回帰生成で過去 token の Key と Value を layer ごとに保存し、次の token を生成するときの再計算を避けるメモリ領域である。生成step t では新しいQだけを計算して保存済みK/Vを再利用する。概算容量は 2 × layers × sequence length × KV heads × head dimension × bytes。MQA/GQAはKV headsを減らし、decode時のcache読込量を削減する。GQAは近年よく見られるが、全モデルに共通する既定ではない。

    7. Transformerモデルの3系統

    この節では、元TransformerのEncoderとDecoderをどこまで残すかを基準に、Encoder–Decoder、Encoder-only、Decoder-onlyの3系統を整理する。それぞれが使うAttention、代表モデル、得意なタスクを比較した後、T5のtext-to-text設計とspan corruptionを詳しく見る。

    系統Attention代表主な用途
    Encoder–DecoderEncoder full + Decoder causal + Cross-attentionTransformer、T5、mT5、ByT5翻訳、要約、text-to-text変換
    Encoder-only双方向full Self-attentionBERT、DistilBERT、RoBERTa文分類、token分類、抽出型QA
    Decoder-only因果mask付きSelf-attentionGPT系、多くの現代LLMnext-token prediction、生成、対話

    T5 family

    T5（Text-to-Text Transfer Transformer）は、翻訳・要約・分類・質問応答など、形式の異なるタスクをすべて「テキストを入力し、テキストを出力する問題」として統一するために提案されたEncoder–Decoderモデルである。タスクごとに専用の出力構造を設計する代わりに、入力の先頭へ指示を付け、同じモデル・同じ学習損失・同じ生成処理を再利用できる。

    タスクT5への入力例出力例
    翻訳translate English to German: That is good.Das ist gut.
    要約summarize: 長い記事本文...記事の短い要約
    感情分類sentiment: この映画は素晴らしいpositive

    この統一形式が必要になった背景は、従来のNLPでタスクごとにモデル構造・損失関数・出力headを作り分けていたため、知識や実装を再利用しにくかったことにある。T5では分類ラベルさえ文字列として生成するため、大規模な事前学習で得た知識を多様なタスクへ同じ手順で転用できる。

    Span corruption：欠けた文章を生成して復元する

    T5の事前学習では、正解ラベルを人が用意する代わりに、元の文章から自動的に問題と正解を作る。文章内の連続した複数tokenをランダムに選んで隠し、その欠落部分をDecoderに生成させる。この課題をspan corruptionと呼ぶ。単語を1個ずつ隠すだけでなく、連続したまとまりを復元させることで、Encoderは前後の文脈を読み、Decoderは複数tokenからなる自然なフレーズを生成する練習を同時に行う。

    具体例

    元の文が The cute dog walks in the park. の場合、入力を The <extra_id_0> walks in <extra_id_1>. とし、正解出力を <extra_id_0> cute dog <extra_id_1> the park <extra_id_2> とする。<extra_id_0> などはsentinel tokenと呼ぶ欠落位置の目印であり、どの復元文字列がどの穴に入るかをEncoderとDecoderへ伝える。

    元論文の設定では、入力tokenのおよそ15%を隠し、1か所あたり平均3 tokenのspanにまとめる。15%という値は文章の大部分を文脈として残しながら、十分な予測問題を作るための設定であり、spanは意味的な句を人が選ぶのではなくランダムに作る。学習後は、翻訳や要約のように入力を読んで別の文字列を生成するタスクへfine-tuningする。

    mT5とByT5：言語と入力単位を変えた派生モデル

    • mT5：T5のtext-to-text設計を多言語データへ拡張したモデル。1つのモデルで多数の言語を扱い、言語間で学習した知識を共有する用途を狙う。
    • ByT5：WordPieceやSentencePieceのような学習済みsubword語彙を使わず、UTF-8のbyte列を直接入力するモデル。綴り揺れや未知語、言語ごとのtokenizer設計を避けられる一方、同じ文章でも系列が長くなり計算量が増えやすい。
    公式資料による補正：ByT5 の byte

    UTF-8の文字は常に2 byteではない。ASCIIは1、アクセント付き文字は2、一般的な日本語の仮名・漢字は3、補助平面のemoji等は4 byteになり得る。ByT5は256種類のbyte値とspecial tokenを語彙にし、長くなりやすいbyte列を扱う。

    8. BERT：Encoder-only の双方向表現

    この節では、BERTがEncoder-only構成で左右両方の文脈を読む仕組みを説明する。ELMoとの違い、WordPieceとspecial token、token・position・segment embeddingから成る入力表現、BERT-baseの層数・hidden size・最大位置を順に確認する。

    BERT は Bidirectional Encoder Representations from Transformers の略で、文章を生成するDecoderを持たず、入力を理解するTransformer Encoderだけを重ねたモデルである。因果maskを使わないため、各tokenは左側と右側の両方を同時に参照できる。例えば bank の表現を、前後に money があるか river があるかによって変えられる。この文脈依存の表現を、分類・固有表現抽出・抽出型質問応答へ利用する。

    ELMoとの関係

    ELMo（Embeddings from Language Models）は、BERT以前に「同じ単語でも文脈によってベクトルを変える」ことを実現したモデルである。ただし、左から右へ読むforward LSTMと右から左へ読むbackward LSTMを別々に学習し、最後に両方向の表現を連結する。各方向のLSTM内部では反対側の文脈を同時には見ない。

    比較点ELMoBERT
    系列の処理forward LSTMとbackward LSTMが、左右の文脈を別々に逐次処理Transformer Self-attentionが、各層で左右の全tokenを同時に参照
    左右文脈の結合独立した2方向の表現を後で連結左右の情報が各Transformer層の内部で相互作用
    下流タスクへの使い方事前学習モデルを主に固定し、得られたベクトルを追加featureとして既存モデルへ渡す小さな出力headを追加し、通常はBERT本体も含めてend-to-endでfine-tuning
    並列計算LSTMは前時刻のstateが必要なため、token方向の並列化が難しい同一層の全tokenをまとめて処理しやすい

    したがって、ELMoは「文脈化した単語featureを既存モデルへ追加する」方式、BERTは「深い双方向Encoder全体を目的のタスクへ適応させる」方式という違いがある。BERTは左右文脈をより早い層から統合でき、モデル本体をfine-tuningすることでタスクに必要な表現まで調整できる。

    入力表現

    BERTは各入力位置について、token embedding + position embedding + segment embedding の3ベクトルを要素ごとに足し、その合計をEncoderへ渡す。これにより「何というtokenか」「何番目か」「文Aと文Bのどちらか」を同時に表現する。

    要素何を表すか具体例と用途
    WordPiece単語を、約30,000個の学習済みsubword語彙へ分割するtokenizerplaying を play と ##ing のように分け、未登録の活用形や珍しい単語も既知部分から表す。語彙を有限に保ち、未知語を減らす。
    [CLS]入力全体を代表させるため、必ず先頭へ置く学習可能なspecial tokenSelf-attentionを通じて全文の情報を集め、その最終hidden stateを感情分類やNSPなど文単位の判定へ渡す。最初から意味を持つのではなく、学習によって集約役になる。
    [SEP]文の終端、または2文の境界を示すspecial token[CLS] 文A [SEP] 文B [SEP] の形で、質問と本文などを1系列へ入れても境界を識別できる。
    Token embeddingWordPiece tokenの意味を表す学習ベクトルplay など各語彙IDをhidden size次元のベクトルへ変換する。
    Position embedding系列内の絶対位置を表す学習ベクトル同じtokenでも1番目と10番目を区別する。BERT-baseでは最大512位置分の表を学習する。
    Segment embedding各tokenが文Aか文Bのどちらに属するかを表す学習ベクトル文ペア入力で、同じ位置系列の中にある2文の役割を区別する。単一文では通常すべてsegment Aを使う。
    Cased / uncased大文字・小文字を別tokenとして保持するかを決める前処理と語彙の設計CasedはAppleとappleを区別し、固有名詞に有利。Uncasedは小文字化して表記揺れと語彙数を減らす。

    BERTのposition embeddingは、元Transformerのようにsin/cosの式から計算する固定値ではなく、位置0〜511に対応するベクトルを学習する絶対位置表である。そのため標準BERTへ入力できる系列はspecial tokenも含め最大512 tokenで、表に存在しない513番目以降をそのまま扱うことはできない。

    9. BERT の事前学習：MLM と NSP

    この節では、人手でラベルを付けずにBERTへ言語表現を学ばせる2つの事前学習課題を扱う。MLMでどのtokenをどの割合で隠して復元させるか、NSPで2文の連続性をどう分類するか、これらが自己教師あり学習と呼ばれる理由を説明する。

    BERTはWikipediaや書籍のような大量の文章を先に読み、一般的な語彙・文法・文脈関係を学ぶ。この段階を事前学習（pretraining）と呼ぶ。人が正解ラベルを付ける代わりに、元の文章を加工して正解を自動生成するため、自己教師あり学習（self-supervised learning）に分類される。事前学習後、少量のラベル付きdataで目的のタスクへfine-tuningする。

    Masked Language Model（MLM）

    MLM（Masked Language Model）は、文章の一部を穴埋め問題へ変換し、隠す前のtokenを予測させる課題である。例えば 猫は魚を食べた を 猫は[MASK]を食べた に変え、正解 魚 を当てさせる。予測には左側の 猫は と右側の を食べた を同時に使えるため、BERTは双方向の文脈を学ぶ。

    すべてのtokenを隠すと文脈がなくなり、まったく隠さないと予測問題にならない。そこでBERTは入力tokenの15%だけを予測対象として選び、その15%を次の3種類に分ける。損失は選ばれた位置の元tokenを正しく予測できたかについて計算する。

    1. 80%を [MASK] へ置換：通常の穴埋め問題として、周囲の文脈から元tokenを復元する。
    2. 10%を別のrandom tokenへ置換：入力tokenが正しいとは限らない状況を作り、単純に見えているtokenを信用するだけの学習を防ぐ。
    3. 10%は元のtokenのまま：通常の文章に現れるtokenについても、文脈に合う表現を学ばせる。

    100 tokenの文章なら、平均15 tokenが予測対象となり、そのうち約12 tokenが[MASK]、残りがrandomまたは unchangedになる。常に[MASK]へ変えない理由は、fine-tuningや実際の入力には通常[MASK]が現れないためである。randomとunchangedを混ぜることで、事前学習時だけに存在する記号へ過度に依存する差を小さくする。

    Next Sentence Prediction（NSP）

    NSP（Next Sentence Prediction）は、2つの文を見せて「文Bは原文で文Aの直後に続いていたか」を二択で判定させる課題である。MLMがtoken同士の関係を学ぶのに対し、NSPは質問と回答、前提と結論のような文と文の関係を[CLS]の表現へ学ばせる目的で導入された。

    ラベル文A文B意味
    IsNext（50%）雨が降り始めた。私は傘を開いた。文Bは元の文章で実際に文Aの次に続いていた。
    NotNext（50%）雨が降り始めた。クジラは哺乳類である。文Bは別の場所からランダムに選ばれ、文Aの次文ではない。

    入力は [CLS] 文A [SEP] 文B [SEP] とし、最終層の[CLS]ベクトルを小さな二値分類器へ渡してIsNext / NotNextを予測する。BERT論文では文ペアを扱う質問応答や自然言語推論へ役立つことを期待した。ただし後のRoBERTaはNSPを外しても性能を改善できたため、NSPが常に不可欠というわけではなく、data量や学習方法の影響も大きい。

    用語の精密化

    BERT論文は “unsupervised” という語も使うが、MLM/NSPはdata自身から正解を生成するため、現在はself-supervised（自己教師あり）と呼ぶ方が明確である。

    10. Fine-tuning と下流task

    この節では、事前学習済みBERTを具体的なタスクへ適応させるfine-tuningを扱う。文分類、NER、抽出型QAでどの出力表現へtask-specific headを付けるかを示し、全パラメータを更新する標準手順と、一部を凍結する選択肢の違いを整理する。

    事前学習済みBERTは「文章を文脈化したベクトルへ変換する共通部品」であり、そのままでは感情ラベルや回答位置を出力しない。そこで目的のタスクに必要な形式へ変換する小さな出力層を追加する。これをtask-specific headと呼ぶ。BERT本体とheadをラベル付きdataで追加学習し、一般的な言語知識を具体的な判断へ適応させる工程がfine-tuningである。

    Fine-tuningの基本手順

    1. 目的のタスクに合わせて入力をWordPiece化し、[CLS]や[SEP]を付けてBERTへ渡す。
    2. BERTが各tokenについて、文脈を反映した最終hidden stateを出力する。
    3. 必要な出力位置へ小さなLinear層などのtask-specific headを接続する。
    4. 正解ラベルとの誤差を逆伝播し、標準手順ではheadだけでなくBERT本体の重みも一緒に更新する。

    Sentiment / 文分類

    文章全体の情報を集めた[CLS]の最終stateをLinear層へ渡し、positive / negativeなどのclass probabilityを出す。入力1件につき1ラベルを選ぶ。

    NER / Token classification

    各tokenの最終stateへ同じ分類headを適用し、人名（PER）・地名（LOC）・組織名（ORG）・その他（O）などを位置ごとに判定する。

    Extractive QA

    質問と本文を1系列に入れ、本文内の各tokenへ「回答開始らしさ」と「回答終了らしさ」のscoreを出す。最も整合するstart/end位置を選び、その間のspanを回答として抜き出す。

    公式BERT論文による補正：標準fine-tuningはBERT本体も更新する

    凍結（freeze）とは、事前学習済みEncoderの重みを固定し、出力headだけを学習することを指す。これは計算量や過学習を抑えたい場合のfeature extraction方式である。一方、BERT論文の標準fine-tuningは、事前学習済みBERTの全パラメータと追加したheadを一緒に更新し、内部表現そのものをタスクへ合わせる。ラベルdataが非常に少ない場合や計算予算が限られる場合には、一部または全部を凍結する選択肢もある。

    一次資料: BERT §4

    長所と制約

    BERTの利点は、大量のラベルなし文章から先に一般的な言語知識を学んでおけることにある。個別タスクでは、ゼロから大規模モデルを学習する代わりに、比較的少量のラベル付きdataで既存の表現を調整できる。この事前学習→fine-tuningという流れにより、感情分類・NER・質問応答など多くの理解タスクへ同じBERTを再利用できる。

    制約なぜ起こるか実務上の意味
    自由な長文生成が不得意Encoder-onlyで、次tokenを1つずつ生成する因果Decoderを持たない分類や抽出には向くが、対話や文章生成にはGPT系などDecoder-onlyモデルが適する。
    入力長は標準で最大512 token学習済みposition embedding表が0〜511までで、Self-attentionの計算量も長さの二乗で増える長文は分割するか、Longformerなど長文向け構造を使う必要がある。
    モデルが大きいBERT-baseでも約110M parametersを持つ学習・推論のメモリと時間が必要で、DistilBERTのような圧縮モデルが有用になる。
    タスクごとのdataと学習が必要出力形式が異なるため、headと正解ラベルを用意してfine-tuningする事前学習済みモデルをそのまま置くだけでは、目的タスクの答えは出せない。

    11. DistilBERT と RoBERTa

    この節では、BERTを基点とする2つの改良方向を比較する。DistilBERTでは知識蒸留によってモデルを小型・高速化する方法を、RoBERTaではdynamic masking、NSPの除去、data量やbatch sizeなど事前学習recipeの見直しによって性能を高める方法を説明する。

    DistilBERT：知識蒸留で小型化

    Knowledge Distillation（知識蒸留）は、大きな teacher モデルの出力分布を教師信号として、小さな student モデルへ判断の傾向を移す圧縮手法である。正解を1クラスだけ示す hard label に加え、各classへの相対的な確信度を含む soft probability を学ばせる。

    teacherとstudentの分布差は、KL divergence（Kullback–Leibler divergence）などで測る。これは一方の確率分布をもう一方で近似したときの情報のずれを表す非対称な量で、0に近いほど分布が近い。temperatureで分布を柔らかくしてからこの差を縮める。DistilBERTはBERT-baseの12層から6層へ減らし、distillation loss、MLM loss、hidden stateを近づけるcosine lossを組み合わせる。

    次の3つの数字は、DistilBERT論文がBERT-baseとの比較として報告した値である。「97%正解する」という意味ではなく、モデルサイズ・推論速度・GLUEベンチマーク上の言語理解性能を、それぞれ別の基準で比較している。

    40%
    BERT-baseよりparameter数を削減（約110M → 約66M）
    60%
    論文の推論速度測定でBERT-baseより高速
    97%
    BERT-baseのGLUE総合scoreに対して保持した割合
    数字の読み方

    40%小型は、主にEncoder層を12層から6層へ減らし、parameter数を約110Mから約66Mへ削減したことを指す。60%高速は論文の特定環境・入力条件で測った推論時間の比較であり、あらゆるhardwareやbatch sizeで必ず同じ倍率になる保証ではない。97%保持は複数の言語理解タスクからなるGLUEの集約scoreをBERT-baseと比べた割合で、全タスクで97% accuracyという意味ではない。

    RoBERTa：BERTの学習recipeを再検証

    Dynamic maskingは、同じ文章でもepochごとにMLMで隠す位置を選び直し、モデルへ多様な穴埋め問題を見せる方法である。元BERTの事前作成済みmaskを繰り返す方式に対し、RoBERTaはmask patternを動的に変える。

    さらにNSPを除去し、より大きいbatch、長いsequence、より大量で多様なdata、byte-level BPEなど学習条件を強化した。BERTが「十分に訓練されていなかった」ことを示し、architectureだけでなくdataとtraining recipeが性能を大きく左右すると結論付ける。

    12. 講義全体のメッセージ

    この節では、ここまで扱った個別技術を、位置表現、学習安定性、推論効率、モデル系統、事前学習目的という設計判断へまとめ直す。モデル名を暗記するのではなく、どの課題に対して何を変更したのかを読み取るための観点を整理する。

    位置は入力からAttention内部へ

    absolute addからrelative bias、Q/K rotationへ移り、score計算と位置を密接に結び付けた。

    安定性と効率は別軸

    Pre-Norm/RMSNormは学習安定性、Sparse AttentionとGQAは長文・decode時memoryを改善する。

    同じTransformerでも目的が違う

    T5は変換、BERTは理解・分類、Decoder-onlyは生成へcomputeを集中する。

    目的関数とdataがarchitecture同様に重要

    MLM/NSP、span corruption、next-token、distillation、dynamic maskingが表現の性質を決める。

    Lecture 2 は「Transformer」という単一図を暗記するのではなく、どこへ位置を入れるか、何を共有するか、どのmaskを使うか、どの自己教師信号で学ぶかを追うことで、モデル名の違いを設計判断として読む視点を与える。

    13. 公式・一次資料で補う専門用語集

    この節では、本文で説明した主要用語を短い定義として再掲し、T5、ALiBi、RoFormer、BERTなどの公式論文・一次資料へ結び付ける。本文を読み返す際の索引と、より詳しく調べるための入口として利用できる。

    Relative Position Bias

    Query–Key scoreへ相対距離に応じた値を加える方式。T5は距離bucketごとのhead別scalarを学ぶ。

    出典: T5

    ALiBi

    Attention with Linear Biases。head別の固定傾きで距離に比例するpenaltyをlogitへ加え、長さ外挿を狙う。

    出典: Press et al. (2022)

    RoPE

    Rotary Position Embedding。Q/Kの2次元ペアを位置角で回し、内積を相対位置の関数にする。

    出典: RoFormer

    Post-LN / Pre-LN

    Residual加算後に正規化するか、sub-layer入力を先に正規化するかの違い。Pre-LNは深い学習を安定化しやすい。

    出典: Xiong et al. (2020)

    RMSNorm

    平均を引かずroot mean squareでscaleを整える。LayerNormからre-centeringとβを省いた簡略形。

    出典: Zhang & Sennrich (2019)

    Sliding-window Attention

    各tokenのAttentionを近傍windowへ限定する疎Attention。Longformerはglobal tokenも組み合わせる。

    出典: Longformer

    Receptive Field

    ある上位表現へ情報が伝わり得る入力範囲。各層のwindowより層を重ねた範囲は広がるが、直接Attention範囲とは異なる。

    出典: Mistral 7B

    MQA / GQA

    Query headは複数のままK/Vを全headまたはgroup内で共有し、KV cacheとdecode帯域を減らす。

    MQA / GQA

    KV Cache

    自己回帰生成で、過去tokenのKey/Valueをlayerごとに保存して再計算を避けるmemory領域。

    出典: Fast Transformer Decoding

    Span Corruption / Sentinel

    連続token spanを固有のplaceholderへ置き換え、target側で欠落spanを復元するT5の事前学習。

    出典: T5

    WordPiece

    subword語彙を学習し、語を既知部分へ分割するtokenization。BERT英語版は約30k語彙。

    出典: BERT

    Segment Embedding

    文ペアのtokenがsegment A/Bのどちらかを示す学習ベクトル。token・position embeddingへ加算する。

    出典: BERT §3.1

    MLM / NSP

    MLMはmasked token復元、NSPは2文が連続かの分類。BERTの自己教師ありpretraining objectives。

    出典: BERT §3.2

    Knowledge Distillation

    大きいteacherのsoft output distributionを小さいstudentへ移し、知識を保ちながら圧縮する。

    出典: Hinton et al. (2015)

    KL Divergence

    確率分布PをQで近似したときの情報差を測る非対称量。蒸留でteacherとstudentの分布を近づけるlossに使う。

    出典: Distilling the Knowledge

    Dynamic Masking

    同じ文でもepochごとにMLM対象を選び直し、より多様なcorruption patternを見せるRoBERTaの手法。

    出典: RoBERTa

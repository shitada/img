    2. Pretraining：taskではなくlanguageとcodeを先に学ぶ

    Traditional MLからtransfer learningへ

    従来はspam detection、sentiment extraction、translationごとに独立modelを学習した。しかしいずれもtext理解を共有するため、既学習modelを再利用するtransfer learningが合理的である。LLMでは、まず大規模pretrainingで一般patternを獲得し、その後taskへadaptする。

    目的関数とdata mixture

    Decoder-only LLMのpretraining objectiveは、prefixを条件に次tokenを当てるcausal language modelingである。

    LPT(θ) = −∑t log Pθ(xt | x<t) 文章・codeを1 tokenずつ右へずらし、各位置で正解tokenのnegative log-likelihoodを最小化する。

    Dataは英語、多言語、codeを含む。講義はCommon Crawl、Wikipedia、Reddit、GitHub、Stack Overflowを例示し、「書かれたものを広く予測することでlanguageとcodeの構造を学ぶ」と説明する。Common Crawlはpublic web crawl corpusを無料提供する非営利projectであり、実際のpretrainingではquality filtering、deduplication、license・privacy・safety処理が別途必要になる。

    3. FLOP・FLOP/s・scaling law・Chinchilla law

    表記意味何を測るか
    FLOP / FLOPsfloating-point operation(s)学習に必要な浮動小数点演算の総量。概ねparameter数×token数×architecture係数で増える。
    FLOP/s（講義ではFLOPS）floating-point operations per secondGPUなどが1秒に処理できる演算の速度。precisionやsparsity条件で値が変わる。

    Kaplanらのscaling lawは、compute、dataset size、model sizeを増やすとlossがpower law的に下がることを示した。大きいmodelは同じtoken数でもlossが低いという意味でsample-efficientでもある。しかしcomputeは有限なので、parameterとtokenのどちらへ予算を配るかが問題になる。

    Chinchilla研究は固定compute下で400超のmodelを比較し、model sizeとtraining token数をほぼ同率にscaleさせるべきだと推定した。講義では覚えやすい目安としてtraining token数 D ≈ 20 × parameter数 Nを紹介する。175B parameterを300B tokenで学習したGPT-3は、この基準ではdata不足の「undertrained」側になる。

    画像の読み解き：表は「大きいほどよい」ではなく、固定computeをmodel幅とdata量へどう分けるかを示す。たとえばmodelだけを巨大化してtoken数を据え置くと、parameterを十分学習させ切れない。

    一次資料による補足：20 token / parameterは普遍定数ではない

    これは特定のdense Transformer、data、optimizer、compute budgetから得た経験則である。architecture、data quality、repeated data、inference costの重視度で最適点は変わる。講義Q&Aでも、実務では小規模pilotから自分のsetupのcurveを推定し、Llama 3のように外挿すると説明した。

    一次資料: Training Compute-Optimal Large Language Models

    Pretraining固有の課題

    • Cost・time・electricity: 講義のorderは少なくとも数百万ドル、modelによっては数千万〜数億ドル。
    • Knowledge cutoff: training corpusを締め切った後の出来事はweightsだけでは知り得ない。
    • Knowledge editing: 新事実を注入しつつ他domainをregressさせないweight更新は難しい。
    • Memorization / plagiarism: 次token予測modelがtraining textを再現するriskがある。

    4. Training loopのmemory内訳と分散parallelism

    Trainingは、parameter初期化、forward pass、loss、backward pass、optimizer updateを繰り返す。問題はparameter以外にも大量のstateを保持する点にある。

    保持物役割主な増加要因
    Parametersmodelの学習対象weight。parameter数、保存precision。
    Activationsforwardの中間値。backpropのchain ruleで必要。batch size、sequence length、layer数・hidden幅。attentionは標準実装でsequence長の2乗項を持つ。
    Gradients各parameterをloss低下方向へ動かす微分値。trainable parameter数、precision。
    Optimizer statesAdamならgradientの1次・2次momentなど。parameter数。master weightを含む実装ではparameter本体より大きくなり得る。

    講義例のNVIDIA H100は80GB VRAMであり、billion〜hundreds of billions級modelの全stateは1枚に収まらない。そこで複数GPUへdataまたはmodel computationを分ける。

    Data parallelismとZeRO

    Data parallelism（DP）はmini-batchをGPU間で分割し、各GPUにmodel replicaを置く。各deviceが独立にforward/backwardを行い、gradientをall-reduceなどで集約・平均して同じupdateを適用する。Batch由来のactivation memoryを分散できるが、modelとoptimizer stateは重複し、通信costも生じる。

    ZeRO stageGPU間でshardするstate意味
    Stage 1Optimizer statesAdam momentやFP32 master stateをrankごとに分担する。
    Stage 2Stage 1 + gradients各rankは担当parameterに対応するreduced gradientだけを保持する。
    Stage 3Stage 2 + parametersweight自体も分割し、必要なforward/backward時だけcollectして再partitionする。

    画像の読み解き：各GPUの細い色付き棒は「全stateのcopy」ではなく各stateの一部分である。memoryは減る一方、必要stateを集める通信が増えるため、常に高stageが最速とは限らない。

    用語補足：shareではなくshard

    講義音声・slideは「share」と表現するが、ZeROの実体はstateのpartition / shardingである。全GPUが同じcopyを共有保持するのではなく、各rankが別のsliceを持つ。

    公式資料: DeepSpeed ZeRO tutorial

    Model parallelism

    方式何を分割するか講義での直観
    Tensor parallelism1つの大きなmatrix multiplication。weight matrixのrow/column方向を複数GPUで計算する。
    Pipeline parallelismlayer群。GPU 1がlayer 1–3、GPU 2が4–6のようにstage化する。
    Expert parallelismMoE expert。異なるFFN expertを異なるdeviceへ配置する。
    Sequence / context parallelismsequence dimension。公式slideに列挙。長いcontextのactivation・attention workloadを分ける方式群。

    5. FlashAttention：演算数よりmemory I/Oを減らす

    GPUには、大きいが相対的に遅いoff-chip HBMと、小さいが高速なon-chip SRAMがある。標準attentionは、score S=QKᵀ、probability P=softmax(S)、output O=PVという大きな中間matrixをHBMへ何度もwrite/readする。このdata movementがcomputeより遅いbottleneckになり得る。

    Attention(Q,K,V) = softmax(QKT / √dk)V

    FlashAttentionはQ・K・Vをblockへ分けるtilingを使い、SRAMに入る小blockだけをend-to-endで処理する。Rowごとのrunning maximumとnormalization sumを更新するonline softmaxにより、全score matrixをmaterializeしなくても最終softmaxと同じ値を得る。

    画像の読み解き：attention matrix全体を保存せず、局所blockの積・softmax統計・Vとの積をon-chipで完結させる。これはsparse attentionのような近似ではなく、丸め誤差の範囲で同じattentionを計算するexact algorithmである。

    Backwardでは保存せず再計算する

    Backwardに必要な巨大attention activationをforward時にHBMへ保存せず、small summary statisticsだけを保存し、必要なblockを再計算する。FLOPは増えるがHBM trafficが大幅に減るため、memoryもruntimeも下がり得る。

    画像の読み解き：「演算を減らせば速い」という単純図式が破れる例である。追加computeより、slow memoryとの往復削減の効果が大きいため、recomputationした方が速い。

    一次資料による補足：IO-awareとは

    Original paperはSRAM sizeを明示したI/O complexityを分析し、sequence lengthに対する標準attentionのquadratic memoryを避ける。FlashAttention 2/3などは同じ核を新しいGPU execution modelへ合わせて改善する。

    一次資料: FlashAttention

    6. Quantizationとmixed precision training

    Floating-point表現

    Floatはsign、exponent、fraction（講義slideではmantissa）へbitを分ける。Exponent bitは表せる値のrange、fraction bitは有効桁の細かさに強く関係する。

    画像の読み解き：FP16とBF16は同じ16 bitでも性質が違う。BF16はFP32と同じ8-bit exponentを保つためrangeが広くoverflowしにくい一方、fractionは7 bitで精度が粗い。FP16はfractionが多いがrangeが狭い。

    手法中心idea典型的な用途・注意
    Quantizationweightやactivationをより少ないbitの離散値へmapする。Memory・bandwidth・対応hardwareのthroughputを改善。scale、zero-point、clipping、outlier処理がqualityを左右する。
    Mixed precisionoperationごとにlow/high precisionを使い分け、master stateは高precisionで保持する。Training speedとmemoryを改善しつつnumerical stabilityを守る。

    講義のmixed precision mental model

    FP32のmaster weightsを保持し、forward activationとbackward gradient計算をFP16で行い、weight updateはFP32へ反映する。Low precisionはmemoryを半減し、Tensor Coreなどで高いFLOP/sを得やすい。

    一次資料による補足：実際のAMPはoperation単位でprecisionを選ぶ

    現代のAutomatic Mixed Precisionは「全部FP16」にせず、matrix multiplicationはlow precision、large reduction・cross entropy・exponentialなど不安定なoperationはFP32へ残す。FP16では小gradientのunderflowを避けるloss scalingも重要である。したがって講義図はprincipleを示す簡略modelである。

    公式資料: NVIDIA Mixed Precision Training Guide

    7. SFT：次token modelをhelpful assistantへ変える

    Pretrained modelは「Can I put my teddy bear in the washer?」を質問として助言せず、training textに続きそうな材質説明などを生成し得る。Pretrainingの目的はassistant behaviorではなく、あくまでcontinuation予測だからである。

    Supervised Fine-Tuning（SFT）は、望ましいinput-output pairをlabelとして与え、pretrained weightsを追加学習する。General assistant向けにinstruction-response pairを使うspecial caseがinstruction tuningである。

    LSFT(θ) = −∑t∈response log Pθ(yt | prompt, y<t) 講義の設定ではprompt tokenにlossを置かず、assistant response部分だけをteacher forcingする。

    画像の読み解き：Modelはuser textをparrotするのではなく、そのinputを条件に望ましいoutput distributionを学ぶ。Causal LM自体は同じでも、どのtokenをlabelとして数えるかがpretrainingと異なる。

    実装補足：prompt maskingは設定で変わる

    Hugging Face TRLではprompt-completion datasetはcompletion-only lossが既定だが、full-sequence lossにも変更できる。Chat形式ではassistant_only_loss=Trueでassistant messageだけを対象にする。講義の説明はresponse-only SFTを指す。

    公式資料: TRL SFT Trainer

    Instruction data mixture

    講義はstory、poem、list、explanation、assistant dialogue、math・reasoning・code、safetyを挙げる。初期datasetはhuman expertが書いたが、現在はstronger LLMでcandidateを生成し、人または別modelがqualityをreviewするsynthetic dataも使われる。

    • Helpful: user intentへ直接応答し、actionableでfluentな回答を学ぶ。
    • Harmless / safety: harmful requestのrefusalや、過度な断定を避けるhedgingをdataとして学ぶ。
    • Generalization: Pretrainingで得た概念知識とSFTで得たtask formatを組み合わせ、未見のdetailへ適応する。
    観点PretrainingSFT / instruction tuning
    DataWeb・code・多言語の巨大corpus。高品質なinstruction-response、human + synthetic。
    規模Hundreds of billions〜trillions of tokens。Thousands〜millions of examples。桁違いに小さい。
    目的Language/codeのgeneral patternと知識。Promptに対する望ましいbehaviorとtask適応。
    LossSequence全体の次token予測。講義ではpromptをmaskしresponse tokenにloss。
    Data quality量とcoverageに加えfilteringが重要。少量でもstyle・factuality・safetyの一貫性が特に重要。
    一次資料による補正：slideの「GPT-3 13 thousand」はInstructGPT

    講義slideはSFT例数を「GPT-3: 13 thousands」としBrown et al. (2020)を引用するが、original GPT-3はinstruction SFTを行っていない。約13k training promptsは、GPT-3をbaseにしたInstructGPTのSFT dataset（Ouyang et al., 2022）の数字である。Llama 3 paperはpost-trainingにmillions of human instructions and preference judgmentsを使ったと記す。

    一次資料: InstructGPT / GPT-3 paper / Llama 3 paper

    8. SFTの難所：data distribution・generalization・cost

    High-quality data

    望ましいstyle・factuality・safetyを満たすhuman reviewは時間と費用がかかる。

    Prompt distribution

    Training promptとproduction promptが離れると、能力があっても適切に引き出せない。

    Generalization

    同じpatternの重複より、task空間を覆う多様なexampleが重要。

    Evaluation

    「helpful」の主観性とfactuality・safetyを単一scoreで同時に測れない。

    Compute

    Pretrainingより小さいが、full fine-tuningは全parameter・gradient・optimizer stateを扱う。

    同一training promptを再入力しても、non-zero temperatureならword-for-wordで同じoutputになるとは限らない。Flavorが似る可能性はあるが、samplingとpretraining distributionにより別のstoryを生成する。Variationを増やしたい場合、temperatureだけでなく、target domainを覆うdataを増やす必要がある。

    9. Evaluation：benchmarkとChatbot Arenaの両方に盲点がある

    Capability benchmark

    Benchmark測るもの一次資料による正確な補足
    MMLUGeneral knowledge / multitask understanding。STEM・humanities・social sciencesなど57 tasksの4択問題。
    ARC-ChallengeScience questionを使うbasic reasoning。ARCのうちretrieval・co-occurrenceだけでは難しいchallenge subset。
    GSM8KNatural-language math reasoning。Grade School Math 8.5K。講義中の「grad school / high school」ではない。
    HumanEvalFunction specificationからのcode generation。164 Python programming problemsをunit testのpass率で評価。

    Benchmark scoreは、test exampleそのもののleakだけでなく、同じtest taskをtrainingしたかにも依存する。Math reasoning formatを大量に学んだmodelと、同taskを見ていないmodelのscore差を「architectureのemergent ability」とだけ解釈すると不公平になり得る。

    一次資料による補足：training on the test task ≠ exact contamination

    Dominguez-Olmedoらは、exact test itemを見せなくてもtask-specific dataで全modelを同条件にfine-tuneすると、MMLU・GSM8Kの世代差や「突然のemergence」が大きく縮むと報告した。比較ではpretraining/post-training mixtureの透明性が重要である。

    一次資料: Training on the Test Task Confounds Evaluation and Emergence

    Chatbot Arena：user preferenceをpairwise voteする

    Chatbot Arenaは匿名の2 modelへ同じpromptを送り、userが良いresponseを選び、pairwise resultからrankingを作る。Open-ended qualityの「vibes」を数値化できる一方、別のbiasを持つ。

    画像の読み解き：Userは読みやすさを判断できても、専門的factualityを検証できるとは限らない。安全上必要なrefusalは「答えなかった」とdownvoteされやすく、voter populationのemoji・verbosity嗜好も全userを代表しない。

    一次資料による補足：model識別を使ったranking操作

    Huangらはresponseからtarget modelを95%超で識別し、約1,000のstrategic votesでもrankingを動かせるsimulationを示した。Rate limit、login、bot detection、reputationなどでattack costを上げられるが、human voteも無条件のground truthではない。

    一次資料: Exploring and Mitigating Adversarial Manipulation of Voting-Based Leaderboards

    結論は「benchmarkかhuman preferenceか」の二者択一ではない。Knowledge、reasoning、code、factuality、safety、latency、target user preferenceなどを分け、use caseに合うevaluation suiteを組む必要がある。

    10. Alignmentとmid-training

    講義では、pretraining後のSFT + preference tuningを広くalignmentと呼ぶ。SFTがinstruction followingを教え、次回扱うpreference tuningがhuman preferenceやsafety policyへさらに寄せる。ただし「alignment」の範囲は文献・組織によって異なる。

    終盤ではmid-trainingも紹介された。Pretrainingとfine-tuningの間に、最終用途へ近いdataを使って同じnext-token objectiveを続ける段階である。Domain-adaptive continued pretraining、long-context adaptation、capability-specific dataの注入などがこの考え方に近い。SFTのようにresponse behaviorだけを教える前に、target domainの表現・語彙・knowledgeへbase modelを寄せる。

    11. LoRA：full weight updateを低rank差分へ置き換える

    Full fine-tuningはweight matrix W全体を更新し、同sizeのgradient・optimizer stateを必要とする。LoRA（Low-Rank Adaptation）はpretrained weight W0をfreezeし、task-specific updateを2つのthin matrixの積で表す。

    W′ = W0 + ΔW = W0 + (α/r)BA W₀ ∈ Rdout×din, B ∈ Rdout×r, A ∈ Rr×din, r ≪ min(din,dout)

    Trainable parameterはfull matrixのdoutdinから、LoRAのr(dout+din)へ減る。α/rはupdate scaleを制御する。講義slideはscaleを省略してW=W₀+BAと示す。

    画像の読み解き：BlueのW全体を再学習せず、grayのW₀は共通baseとして固定し、greenのsmall matricesだけを保存する。Spam、sentiment、translationごとにA/Bを交換でき、1つのbase modelから複数taskを運用しやすい。

    • Original LoRAは主にattention projectionへ適用し、taskごとにsmall adapterを保存する。
    • Inference時にBAをW₀へmergeすれば、追加layer latencyを避けられる。
    • Rank rはcapacityとmemoryのdesign choice。講義はgrid searchも可能で、r=4をcommonな例として挙げる。
    • Prefix tuningやadapter layerもparameter-efficient手法だが、講義ではLoRAほど深掘りしない。
    用語補足：low rank

    Matrix rankは独立な方向の数である。BAのrankは最大rなので、LoRAは「task適応に必要なweight変化は、full parameter空間より低次元で表せる」という仮定を置く。Parameterを単に一部選ぶのではなく、全入出力dimensionへ作用する低次元updateを学ぶ。

    一次資料: LoRA

    12. LoRAの更新guidance：MLP、learning rate、batch size

    講義は2025年9月のThinking Machines Lab記事「LoRA Without Regret」を使い、original paper以後の実務guidanceを更新する。

    画像の読み解き：Original experimentのQ/V attention projectionだけでなく、modern recommendationはMLPを含む全linear weightへLoRAを置く。MLP-onlyがattention-onlyを上回り、MLP+attentionと近い場合も報告された。

    Guidance一次資料の観察解釈
    Target modulesAll weight matrices、特にMLP/MoEへ適用。Attention-onlyはparameter数を合わせても劣る。Task updateの重要方向がattentionだけに閉じていない。
    RankDatasetがadapter capacityを超えるとFullFTよりlearning efficiencyが落ちる。小さいrを常に選べばよいわけではなく、data scaleに合わせる。
    Learning rateHigh-rank LoRAのoptimal LRはFullFTの約10倍だった。FullFTのhyperparameterをそのまま流用しない。
    Batch size一部SFT設定でlarge batchへのpenaltyがFullFTより大きく、rank増加でも消えない。BAというproduct parameterizationのtraining dynamicsがfull matrixと異なる。
    適用範囲に注意

    これらはTulu3・OpenThoughts3などでのempirical resultで、全model・datasetへの定理ではない。記事自身もsmall-to-medium post-training dataではLoRA≈FullFT、adapter capacityを超えるvery large dataではunderperformすると区別する。

    一次資料: LoRA Without Regret / 公式再現guide: Hugging Face TRL

    13. QLoRA：4-bit frozen base + BF16 LoRA

    QLoRAはLoRAのW₀を4-bitで保存し、A/B adapterはBF16など高いprecisionで学習する。Forward/backward時はquantized weightをcompute dtypeへdequantizeし、gradientは凍結baseではなくLoRA matricesへ流す。

    NF4とdouble quantization

    NF4（4-bit NormalFloat）はpretrained weightが概ねzero-centered normal distributionに従うことを利用し、uniformな数値幅ではなくnormal distributionのquantileに基づくcodebookを置く。各binへおおむね同数のweightが入るため、4 bitをweight密度の高い領域へ効率よく割り当てる。

    画像の読み解き：Weightが集中する0付近を細かく、tailを粗く表す。Fixed-width bucketでは頻出領域の誤差が大きくなりやすいが、quantile基準は有限codeを分布へ合わせる。

    Quantizationにはblockごとのscale constantが必要である。Double quantizationはweightだけでなく、このconstant自体もquantizeする。Original QLoRA paperのもう1つの要素はpaged optimizerで、long sequenceの一時的なmemory spikeをNVIDIA unified memoryで退避する。講義は時間の都合でここを説明していない。

    >780GB → <48GB
    LLaMA 65Bの16-bit FullFTからQLoRAへのpaper記載memory削減。
    0.37 bit/param
    Double quantizationの平均追加saving。65Bで約3GB。
    4-bit + BF16
    Frozen base storageはNF4、LoRA parameterとcomputeは高precision。
    講義の「約16× VRAM saving」を精密化

    Paperはregular 16-bit fine-tuningの780GB超を48GB未満へ下げ、65B modelをsingle 48GB GPUでfine-tune可能にしたと報告する。Double quantizationだけの効果は平均0.37 bit/parameterであり、全体の16×はNF4、LoRA、paged optimizerを含むsystem効果である。

    14. 講義内Q&A総覧

    質問講義の回答・要点
    Model version間でpretrainingをtransferするのか。Closed modelはrecipeを公開しないため一般回答はできない。いずれにせよpretrainingは高価。
    Scaling lawでarchitecture差は重要でないのか。Paperのtested familyではparameter・tokenが主要因。ただしlawを別architectureへ無条件に外挿しない。
    Data parallel GPU間のgradient updateは。各mini-batchのgradientを通信でaggregateし、平均に相当するupdateを全replicaへ適用する。
    FlashAttentionはrow全体をSRAMへ入れるのか。図は説明用。実際はSRAM sizeに合わせQ/K/Vを2次元blockへ分けられる。
    Online softmaxの補正係数は近似か。Running statisticsを逐次計算するexact method。詳細式はpaper参照。
    Mixed precisionは全layerへ同じように適用するか。Variationがあり、重要な部分を高precisionへ残す。実装・hardware依存。
    Quantizationのrangeをどう扱うか。講義はzero-point・absmax quantizationをpointerとして挙げ、QLoRAのNF4へつなぐ。
    SFTでinputにもlossを置くか。講義のinstruction settingでは置かず、response開始からlossを計算する。
    同じSFT exampleを入れると同じoutputか。Non-zero temperatureなら同じwordingとは限らない。類似flavorはあり得る。
    LoRA rankはgrid searchするか。可能。既知のpopular valueから始めてもよく、講義はr=4を例示。Dataset capacityとの対応を確認する。

    15. 難しい用語の補足

    用語この講義での意味
    Base / pretrained modelLarge corpusで次token予測を終えたが、assistant behaviorへ十分alignしていないmodel。
    ActivationLayerがforward時に出す中間tensor。Backwardでgradientを計算するため保持または再計算する。
    Optimizer stateAdamの1次・2次momentなど、parameter updateを安定化する補助state。
    HBM / SRAMGPUの大容量off-chip memory / 小容量高速on-chip memory。FlashAttentionは両者間のI/Oを最適化する。
    All-reduce複数rankのgradientをsumし、結果を全rankへ配るcollective communication。
    ShardingTensorやstateをsliceへ分け、deviceごとに別sliceを持つこと。Replicationの反対。
    Quantization scale / zero-pointInteger codeと実数値を対応させる倍率 / zeroのcode位置。Range・誤差を決める。
    Low rankMatrixの独立方向が少ないこと。LoRAではtask updateをrank rのsubspaceへ制限する。
    Out-of-distributionTraining prompt/dataとdeployment inputの分布がずれた状態。Generalization failureの一因。
    Data contaminationTest itemまたは非常に近いdataがtrainingへ混入し、benchmarkが実力以上に見えること。

    16. まとめ：各手法はどのbottleneckを解くか

    課題手法得るもの新しいtrade-off
    Taskごとにゼロから学習Pretraining + transfer learning共通知識を再利用。巨大な初期cost、cutoff、memorization。
    固定computeの配分Scaling / Chinchilla lawParameterとtokenの設計指針。Empirical lawはsetup依存。
    Model stateが1 GPUに収まらないDP / ZeRO / model parallelismAggregate memoryとcomputeを利用。Communication・scheduling cost。
    AttentionのHBM trafficFlashAttentionExact attentionのmemory・runtime削減。Kernel・hardware-specific tuning。
    FP32のmemory・throughputMixed precision / quantization少ないbytesと高速hardware path。Overflow、underflow、rounding error管理。
    Base modelがinstructionへ答えないSFT / instruction tuningHelpful・task-specific behavior。High-quality data、distribution、evaluation。
    FullFTのtrainable stateが大きいLoRASmall task adapter、swap・merge可能。Rank capacity、LR・batch dynamics。
    Frozen base weightも大きいQLoRA4-bit storageでsingle-GPU fine-tuning。Quantization kernel、dequantization、quality検証。

    講義の一貫したmessageは、LLM trainingを単なる「大きなmodelへ大量dataを流す作業」と見ないことにある。Knowledgeを得るstage、behaviorを教えるstage、memory state、I/O、precision、evaluationへ分解すると、各techniqueが何を節約し、何を新たなcostとして持ち込むかが見える。
